# История версий GIGACODE-пакета

## 2.3.1 — 2026-10-14

- В `qa-test-cases` встроен отбор до детализации: самостоятельный кейс,
  встроенная проверка, предусловие, вопрос или обоснованное исключение.
  Сохранены обязательные критерии, различия UI/API, права, границы и редкие риски.
- Стандарт шагов требует подтверждённой подготовки, конкретных действий и
  различающих наблюдений; неизвестная подготовка отделена от временной
  недоступности ресурса и не дополняется выдуманными инструкциями.
- Шаблон контекста описывает возможности и ограничения проверки; заполненный
  контекст проекта при init/update сохраняется. Автор и reviewer используют
  общий маршрут без изменения событий и JSON-схемы каталога.
- Управляемый bare-автор получает навык и правила отбора в замороженном контексте;
  reasoning benchmark получает те же предметные инструкции для новых прогонов.
  Исторические результаты и хеши не пересчитываются.
- Добавлены 15 синтетических кандидатов, отдельные ориентиры ревьюера, готовый
  JSON-пример и назначение для пилота на реальной задаче. Учебный набор и локальные
  проверки не подтверждают качество живого GIGACODE. Автоматический барьер
  публикации и новые поля TMS остаются следующей итерацией.

## 2.3.0 — 2026-10-14

- Исправлены сценарии промышленного ревью: полная предвалидация кандидата,
  независимый rollback, сохранность контекста, CAS перепривязки, защита чтения binding.
- Для автообновления main нужен успешный CI точного SHA. CI сохраняет ZIP/checksum;
  при недоступности проверки запуск остаётся на известной версии.
- Внешний recovery zipapp, backup hashes/права, журнал phases и fsync markers
  позволяют откатить собственный fast-forward и продолжить прерванное переключение.
- Init/configure согласуют записи блокировкой каталога; контекст создаётся без замены.
  CLI rebind требует показанный binding SHA-256, библиотека — snapshot/digest.
- MCP сохраняет ограничения JSON и обслуживает следующие сообщения после ошибок.
  Добавлены регрессии гонок, FIFO, missing imports, CI gates и fault injection.
- Новый протокол не мигрирует старый pending без backup. Нужны Git 2.36+,
  локальный POSIX FS и живой пилот GIGACODE/registry; физический power-loss не измерен.

## 2.2.1 — 2026-10-14

- Добавлены read-only MCP `qa_tasks_list`/`qa_task_get`: поиск локальных реестров,
  страницы, фильтр завершённых задач, владельцы, критерии и ссылки/hashes материалов.
- `/qa:tasks` показывает задания, `/qa:resume <ID>` восстанавливает выбранное;
  пустая `/qa` предлагает выбор или новую цель. Снимок не разрешает новый запуск.
- Закреплена единая раскладка новых планов, кейсов, расследований и доказательств;
  старые явные пути и исторические артефакты не мигрируют автоматически.
- Чтение реестров ограничено по размеру/области, отвергает FIFO и симлинки,
  отмечает повреждённые записи/дубликаты, не выдаёт delivery tokens или сырые события.
- MCP переживает глубоко вложенный и чрезмерно длинный JSON. Локальные тесты
  проверяют файловую безопасность и восстановление снимка; живой CLI требует пилота.

## 2.2.0 — 2026-10-14

- Stdio MCP расширения дополнен `qa_project_init` и read-only `qa_project_doctor`:
  прямые вызовы функций без subprocess, кроме существующего CLI version probe.
- Init требует абсолютный путь, идемпотентно пишет только три файла привязки;
  ошибки выполнения возвращаются как `isError` с текстом `QA project error: …`.
- Перепривязка требует предварительного ответа со старым/новым путём и второго
  вызова в той же MCP-сессии. Агент показывает пути и проверяет разрешение переноса.
- `needs_attention` — штатный результат doctor. Команды и инструкции используют
  MCP первым, CLI — fallback при недоступности инструмента.
- Добавлены проверки границ записи, ошибок, схем tools, двухшагового переноса
  и read-only диагностики. Живая загрузка tools требует пилота GIGACODE.

## 2.1.5 — 2026-10-14

- Исправлен способ установки: сначала локальный Git clone, затем install по
  абсолютному пути. Git URL больше не предлагается как аргумент install.
- Добавлен `qa-start`: автоматическая проверка и fast-forward источника до
  начала QA-сессии, штатное обновление установленной копии и освежение привязки.
- Активные сессии и managed-задачи откладывают замену пакета; локальные правки,
  расхождение веток и коммит без новой версии не перезаписываются.
- Офлайн-запуск сохраняет установленную версию. Намерение обновления хранится
  до применения; после сбоя выполняется readback, частичная установка блокирует запуск.
- Добавлены проверки локальных Git-репозиториев, сохранности контекста, блокировок,
  восстановления и перезапуска нового кода. Живой менеджер CLI требует пилота.

## 2.1.4 — 2026-10-14

- Пакет оформлен как `gigacode-extension.json`: роли, skills, команды и отдельный
  контекст расширения. Версия манифеста проверяется упаковщиком вместе с VERSION.
- Добавлены `/qa:init` и `/qa:doctor`: привязка проекта к пакету, сохранение
  контекста приложения, обновление версии без копирования исходников и диагностика.
- Read-only MCP `qa_package_info` возвращает фактические пути и версию пакета;
  запуск не зависит от текущей директории приложения или имени домашнего каталога.
- Инструкции различают корни пакета/проекта; локальная привязка, managed-состояние
  и QA-доказательства исключаются из Git приложения. Auth/MCP приложения сохраняются.
- Добавлены проверки stdio MCP, сохранности проекта, обновления, переноса,
  некорректных привязок и упаковки. Живая загрузка расширения целевой сборкой
  GIGACODE остаётся предметом пилота; наличие файлов её не подтверждает.

## 2.1.3 — 2026-10-13

- Добавлен генератор ручных JSON-каталогов в Allure без выполнения тестов:
  стабильные ID, scoped-сопоставление существующих TestOps ID и audit manifest.
- Добавлены отдельные Jenkins-шаблоны проверки веток и публикации основной
  ветки по вебхуку GitVerse; отправка по умолчанию выключена до пилота.
- Генератор отклоняет повторяющиеся JSON-ключи, некорректную версию схемы и
  символические ссылки; идентичность кейсов исключает неоднозначные границы
  namespace/ID. Jenkins очищает рабочую директорию перед checkout.
- Документированы настройка инфраструктуры, ограничения Allure-представления
  и обновление с 2.1.2. Реальные параметры систем собираются при подключении.
- Установлено правило повышения версии для каждого коммита изменений поставки.
  Локальная проверка: 598 тестов; живые GitVerse/Jenkins/ТестОпс требуют пилота.

## 2.1.2 — 2026-10-13

- Текущая поставка очищена от документации и протоколов прежней среды исполнения.
  Исходные исторические файлы сохраняются в истории Git.
- Сравнение метрик требует явного backend и идентичности CLI; неполные и старые
  форматы отклоняются без автоматического приписывания результатов новой среде.
- Обновлены ссылки, установка, переход и упаковка текущего профиля GIGACODE.

## 2.1.1 — 2026-10-13

- Основной профиль GIGACODE CLI: `.gigacode/`, `GIGACODE.md`, 14 ролей, 5 skills и `/qa`.
- Общие правила вынесены в `docs/COORDINATOR.md`; добавлены `AGENTS.md` и
  конфигурация исполнителя `qa-runtime.json`.
- Headless-запуски используют общий CLI-адаптер, `--cli`/`--runtime-config`,
  preflight возможностей и нейтральные поля метрик. Несовместимый CLI останавливается до задания.
- Добавлены инструкции, упаковка и CI. Локальная приёмка — 582 теста и отдельный
  учебный пример данных; живой GIGACODE и внешние интеграции требуют пилота.

История более ранних поставок доступна в предыдущих коммитах репозитория.
