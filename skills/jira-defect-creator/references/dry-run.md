# Переносимый dry-run без подключения

Учебный сценарий для проверки порядка и остановки при неизвестных данных.
Не наблюдение продукта, не испытание живой модели и не замер Jira-проекта.
Реальный текст дефекта, проект и подключение при создании навыка не заданы.

## Ввод

«В каталоге заказов выбираю фильтр “Завершённые”, перехожу на вторую страницу.
Выбранный фильтр сбрасывается и появляются заказы других состояний. Ожидаю,
что выбранный фильтр сохранится. Версию сборки и адрес стенда пока не знаю».

## Разбор и подготовленное описание

Заголовок: «Фильтр состояния заказов сбрасывается при переходе на вторую страницу».

Окружение: каталог заказов; стенд и сборка не указаны.

Шаги:
1. Открыть каталог, в котором есть больше одной страницы завершённых заказов.
2. Выбрать фильтр «Завершённые».
3. Перейти на вторую страницу результатов.

Фактический результат: выбранный фильтр сбрасывается, видны другие состояния.

Ожидаемый результат: выбранный фильтр сохраняется при переключении страниц.
Источник ожидания — условие учебного обращения; независимое требование не дано.

Условие о нескольких страницах выведено из шага обращения и подлежит уточнению;
самостоятельно создавать данные или утверждать воспроизведение нельзя.
Разметка показана обычным текстом для просмотра; Jira-рендеринг не проверен.

## Чек-лист dry-run

| Что | Состояние |
| --- | --- |
| Текст и четыре секции | Подготовлены; факты взяты только из учебного ввода |
| Инстанс, проект, тип дефекта | Не заданы; сначала нужен минимум для безопасного поиска |
| Дубли | Не проверены: подключения нет; вывод об отсутствии дублей запрещён |
| Схема, критичность и проектные поля | Не измерены; default не подставлены |
| Стенд/сборка, источник ожидания | Требуют уточнения |
| Секретность и неназначенный исполнитель | Поведение Jira не проверено |
| Связь и релиз/история | Правило не задано; цель не выбрана |
| Payload / хеш | Не сформированы: allowlist и типы неизвестны |
| Внешние вызовы | Отсутствуют; «ок» в этом режиме не разрешает write |

Результат: черновик готов к уточнению, публикация **blocked**. Один пакет
недостающих параметров: инстанс/проект/подключение, реквизиты настройки из
discovery.md и недостающие условия дефекта. После получения минимальной
идентичности сначала поиск, затем остальные уточнения и новое согласование.
Для QA-пакета дополнительно нужны принятое defect_confirmed и jira_assignment.

Локальные автоматические тесты helper используют отдельные явно синтетические
профили с доменом `.invalid`; их значения не переносятся в рабочий профиль.
