# Различающая сила и границы вывода

Примеры синтетические. Они не дают продуктовых требований или полномочий.

| Случай | Решение и основание |
| --- | --- |
| Источник явно требует собственный paid A и исключение unpaid B/чужого paid C | Сохранить: подготовить и подтвердить A/B/C; наблюдать сохранение A и отсутствие B/C. Точное равенство набора допустимо при изолированном наборе и известном контракте пагинации. Пустая выдача не проходит. |
| При том же правиле assert проверяет 200 и len>0 | Переработать: B/C всё ещё могут присутствовать. Проверять требуемый состав/свойства. 200 остаётся технической частью ответа. |
| Два сценария различаются только номерами в одном классе; условия и ошибки одинаковы | Объединить с картой прежних ID и сохранённых рисков. Чужой владелец, граница и отсутствие совпадений — самостоятельные классы, если меняют ошибку. |
| Запрет чужого объекта подтверждён, второго аккаунта/объекта нет | Сохранить: проектирование готово, исполнение ожидает вторую роль и объект с подтверждённой принадлежностью. Review кода не выдавать за реальный отказ API. |
| Внутренний rollback предлагается проверить только по UI; API/логи/БД не предоставлены | Переработать способ наблюдения или запросить доступный наблюдатель. UI подтверждает только внешний эффект. Согласованный риск целостности остаётся непроверенным. |
| Предложен SLA на миллион записей, норматив и нагрузочное исследование не согласованы | Вне области: не придумать порог. При значимом риске предложить отдельное исследование с источниками и условиями. |

Контролируемая ошибка на локальной fixture доказывает силу assert против этой
ошибки. Исключение во время подготовки не доказывает её обнаружение. Наблюдение
свойства только на первой странице не доказывает состав всех страниц.
