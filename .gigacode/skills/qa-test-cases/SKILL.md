В режиме GIGACODE extension пути `docs/`, `scripts/`, `examples/` и `.gigacode/` относятся к установленному `package_root`, а продуктовые файлы и артефакты — к `project_root`. Получи оба абсолютных корня и версию из назначения координатора; при их отсутствии восстанови привязку по `docs/EXTENSION_RUNTIME.md` до работы. Скрипты запускай по абсолютному пути из рабочей директории проекта; передавай явно назначенные пути данных и состояния.

# Тест-кейсы QA

1. Прочитай `docs/TEST_CASE_STYLE.md` — единый источник правил именования и структуры. Определи `test_type` (`api` или `ui`) из назначения. Если тип не передан, определи его по способу проверки; уточни только при неоднозначности. Для смешанной задачи раздели кейсы на API- и UI-группы.
2. Для текущей группы прочитай только `examples/test-cases/<test_type>/INDEX.md` и один JSON-пример, соответствующий цели проверки. Не читай индекс другого типа и не загружай каталог примеров целиком. Дополнительный пример нужен только для существенного аспекта, не показанного первым; для отдельной группы выбирай пример отдельно. Если подходящего примера нет, используй ближайший по оформлению или общий стандарт, не добавляя чужой сценарий в покрытие.
3. Примеры учебные: не переноси из них HTTP-коды, диапазоны, тексты, URL, права или данные в реальные кейсы без подтверждения требованиями. API-кейс описывает запрос (метод, путь, заголовки и body по необходимости) и наблюдаемый ответ/эффект; UI-кейс — действия пользователя и видимый результат. Секреты обозначай ссылкой на способ получения тестового доступа, не значениями.
4. Свяжи каждый кейс с требованием или риском и источником ожидаемого результата. Сохрани `scenario_id` существующего кейса, если проверяемое поведение не изменилось.
5. Сохрани каталог в отдельном JSON-артефакте. В плане оставь только стратегию и таблицу «критерий/риск → ID кейсов → приоритет, способ проверки и доказательство». Не дублируй шаги, предусловия и ожидаемые результаты ни в плане, ни в сообщении координатору: передай пути и резюме покрытия.
6. Запусти `python3 scripts/validate_test_cases.py --input <путь-к-каталогу>`. Исправь ошибки валидатора до передачи результата. Содержательное соответствие требованиям проверь отдельно: валидатор его не доказывает.
