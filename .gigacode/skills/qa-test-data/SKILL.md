# Данные, различающие поведение

Кандидат для измерения: польза для живого GIGACODE пока не установлена. Стандарт остаётся в [TEST_DATA.md](../../../docs/TEST_DATA.md), не копируй его в новый отчёт.

В существующем профиле свяжи каждую именованную запись с назначенным сценарием и ошибкой, которую она позволяет заметить. Для фильтра нужны подходящая запись и различающиеся неподходящие записи: чужой владелец и неподходящий статус ловят разные ошибки. Пустой набор не проверяет ни одну из них. Если тестируется переход, подготовка заканчивается **до** перехода; установка конечного статуса не заменяет его выполнение.

Получай краткий контекст через `scripts/read_test_data_guide.py --role qa-test-data-builder`. Дочитай через `--only-sections --section isolation` при параллельных worker, изменяемых общих данных или неизвестном результате создания; `--section cleanup` при частичном сбое; `--section recipe` при выборе механизма. Если контекст уже передан, используй его без повторного чтения.

При timeout создания ищи фактическое состояние по исходной корреляции перед повтором. Отдельно отмечай: запланированный рецепт, найденные/созданные ID, проверенные свойства, незавершённую подготовку и остатки очистки. Разделяй готовые и заблокированные сценарии по фактическим свойствам; непроверенная связь с платежом или видимость для роли не становится готовой от ответа создания. Очистка охватывает только подтверждённые ресурсы своей попытки и сохраняет исходную ошибку.
