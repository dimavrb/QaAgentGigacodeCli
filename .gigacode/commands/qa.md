description: Передать QA-задачу оркестратору qa-agent
---

Выполни задачу пользователя как координатор qa-agent в текущей сессии.

Если существует `qa-agent/APP_COORDINATOR.md`, прочитай его как инструкции установленного QA-проекта; иначе прочитай `docs/COORDINATOR.md`. Соблюдай применимые правила проекта приложения. Для маршрута и контракта результата загружай только нужные разделы документов по путям из инструкций координатора.

Выбери подходящий QA-маршрут и делегируй работу нужным ролям `qa-*`, когда отдельный исполнитель необходим. Проверь результаты по контракту, сохрани ссылки на доказательства и явно отметь блокеры. Для браузерной проверки используй `qa-browser-repro`, для создания или существенного изменения каталога кейсов — `qa-test-cases`.

Для новой задачи создай общий реестр и используй проверяемую передачу по TASK_EXCHANGE.md из применимых инструкций координатора. Резервируй назначение до запуска, регистрируй результат полным валидатором и фиксируй содержательное принятие до передачи зависимому исполнителю. Ответы формы и отдельный запуск автотестов подключай к тому же реестру через --task-state.

Если задание пустое, запроси цель QA-задачи; не запускай проверки без задания. Не расширяй объём внешних действий за пределы запроса пользователя.

Требуй короткую самопроверку окончательного результата всех исполнителей по docs/SELF_REVIEW.md; перед этапом и итогом сверяй обязательные условия и принятые доказательства. self_review не заменяет отдельного содержательного принятия.
