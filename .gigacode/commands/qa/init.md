---
description: Подключить текущий проект к QA Agent extension и сохранить контекст приложения
---

Подключи текущий проект к установленному QA-пакету. Получи фактический
`package_root`, `package_version` и `project_tool` через MCP `qa_package_info`.
Определи абсолютный `project_root` из текущего рабочего проекта, а не из каталога
установки расширения. Прочитай `<package_root>/docs/EXTENSION_RUNTIME.md`.
Если MCP недоступен целиком, возьми проверенный installed path из менеджера
расширений и получи метаданные через `python3 "<package_root>/scripts/qa_project.py" info`.
Не угадывай путь и не используй одноимённый скрипт приложения.

Вызови MCP `qa_project_init` с `{"project_root":"<project_root>"}`; путь обязан
быть абсолютным. Инструмент вызывает `initialize()` напрямую, без shell/subprocess.
Ошибку `isError` с текстом `QA project error: …` покажи пользователю.
При несовпадении пути сначала вызови инструмент без `rebind`, покажи возвращённые
старый/новый пути и установи причину. Только для разрешённого переноса вторым
вызовом в той же MCP-сессии передай `rebind=true`. Если пути изменились или MCP
перезапущен, сначала повтори показ. Сам показ не является разрешением переноса.
Если MCP-инструмент недоступен, используй CLI fallback:
`python3 "<project_tool>" init --project-root "<project_root>"`.
Для fallback сначала прочитай старую локальную привязку и покажи оба пути;
`--rebind` применяй вторым шагом только для разрешённого переноса.
Не обходи ошибку MCP переключением на CLI; fallback нужен при недоступности инструмента.
Не удаляй прежнее подключение `qa-agent/APP_COORDINATOR.md` автоматически.

Инициализация пишет только `.gitignore`, `.qa-agent/APP_CONTEXT.md` и
`.qa-agent/project.local.json`; существующий контекст сохраняет. Последующее
заполнение контекста выполняй в рамках QA-задачи: изучи правила приложения и
укажи только подтверждённые факты. Неизвестное оставь
как `не настроено`; не спрашивай параметры Jenkins/ТестОпс до поручения готовить
эту инфраструктуру. Не устанавливай MCP, модель или авторизацию этой командой.

Выполни `/qa:doctor` и сообщи версию, изменённые файлы и пределы проверки.
`configured` подтверждает локальное подключение файлов, а не готовность стенда.

Для автоматического обновления перед следующими сессиями покажи пользователю
настройку `qa-start` из `<package_root>/docs/AUTO_UPDATE.md`. Источник должен быть
той локальной Git-копией, которую передали менеджеру при установке. Не запускай
обновление пакета внутри уже открытой сессии и не меняй shell-профиль автоматически.
