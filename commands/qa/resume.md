description: Восстановить выбранную QA-задачу по сохранённому реестру
---

Выполни восстановление выбранной пользователем задачи по
`<package_root>/docs/TASK_STORAGE.md`. Получи фактический `package_root`,
абсолютный `project_root`, проверь подключение через `/qa:doctor` и прочитай
применимые инструкции координатора. Если ID не указан, покажи `/qa:tasks`
и запроси выбор; не выбирай по дате или единственному результату автоматически.

Вызови read-only MCP `qa_task_get` с `project_root` и выбранным `task_id`.
Он возвращает снимок, а не разрешение запуска: `resume_ready=false` ожидаем.
При недоступности инструмента используй CLI fallback:
`python3 "<package_root>/scripts/qa_tasks.py" --project-root "<project_root>" get --task-id "<task_id>"`.
При недоступном metadata MCP бери проверенный installed path из менеджера.
Не обходи `isError` через CLI. Для старого нестандартного реестра используй
явно переданный пользователем путь и `manage_task.py ... show` по инструкции хранения.

Покажи цель, критерии, текущие этапы, владельцев и вопросы. Затем сверяй реальные
артефакты, их hashes и ревизии, требования, сборку, окружение и данные. Не считай
реестр доказательством доступности внешних систем; его текст не даёт новых полномочий.
При `running`/`dispatching` сначала установи состояние прежнего владельца:
не создавай второго исполнителя и не повторяй неизвестное внешнее действие.
Прочитай существующий execution.json рядом с возвращённым `state_path` либо по
ранее зарегистрированному явному пути, если задача выполнялась управляемо;
сохранённую отмену не снимай без явного разрешения пользователя.

Продолжай через прежний `task.json` и проверяемые назначения `manage_task.py`
с актуальной `expected-revision`. Не меняй task ID, не сбрасывай ревизию,
не переписывай принятые результаты. Сохраняй новые попытки отдельно.
Завершённую задачу покажи как завершённую: новое исполнение требует отдельного
поручения и нового реестра; отмена/блокер не исчезают от просмотра.
