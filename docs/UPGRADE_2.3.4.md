# Обновление до 2.3.4

1. Завершите активные назначения, проверьте внешние действия и обновите весь
   пакет по [EXTENSIONS.md](EXTENSIONS.md). Сверьте VERSION и манифест: 2.3.4.
   Личную конфигурацию, реестры и доказательства сохраняйте вне поставки.
2. Откройте новую сессию, проверьте qa_package_info, `/qa:init` и `/qa:doctor`.
   Для нового назначения настройщика подготовьте environment_assignment по
   [ENVIRONMENT_READINESS.md](ENVIRONMENT_READINESS.md). Проверьте весь текст
   гайда, полноту списка, целевой стенд/версию и связи сценариев.
3. Новые ready/partial требуют guide_checks каждого пункта. Без доступного
   гайда возвращается blocked. Для прямого валидатора задавайте
   --require-environment-checks, --environment-assignment и все --scenario-id.
   Относительные evidence по умолчанию разрешаются от каталога результата;
   при другой базе передайте --environment-evidence-base.
4. Старые реестры и отчёты не дополняйте задним числом и не пересчитывайте хеши.
   Для новой проверки прежнего стенда создайте новое назначение, снимок и
   наблюдения. После изменения инструкций создавайте новый managed-план;
   учтите ранее выполненные внешние действия перед повтором.

Штатный синтетический пример — examples/environment-readiness. Старый
examples/task-exchange сохранён для аудита прежнего формата. Установка пакета
и локальные фикстуры не подтверждают готовность реального стенда.
