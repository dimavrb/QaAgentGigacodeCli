# QA-пакет 2.3.15 — контекст координатора и надёжная передача QA-ролей

## Гейты отказов QA-ролей

COORDINATION_SAFETY.md задаёт проверяемые правила новых назначений: единственный
тяжёлый слот с учётом координатора, пересечение inputs/выходов до assign,
побайтовые snapshots принятой базы, абсолютные локальные пути и источники,
неизменяемые evidence вне .qa-agent-state/, сопоставление владельца с runtime
и readback результата до признания сдачи. Для failed/429 сначала инвентарь
сохранённых наблюдений, затем переоформление; живой reviewer без result получает
только точечное продолжение на запись/сдачу.

Все 14 ролей содержат правила сохранения работы, guard-профиля, self_review
и передачи запрещённой валидации/хеширования координатору. Протокол ревью
явно требует boolean blocking и blocking=true для changes_requested.
QUESTIONS_UI различает запись serve, наблюдение wait и ручной экспорт build;
обязательны чтение overall_comment и сохранение deferred открытым до решения.

Изменены только Markdown-инструкции и их native-копии. Код гейтов и guard
не менялся: перечень необходимых программных гарантий выделен в слой B
COORDINATION_SAFETY. Исходный журнал из 11 инцидентов и метаданные другого
проекта недоступны; правки опираются на постановку и проверенные механизмы
контрактов. Исчезновение инцидентов и качество живой модели не заявляются.

## Сокращение вывода координатора

Раньше prepare целиком печатал назначение и критерии, уже сохранённые
координатором. Теперь `prepare --output <новый handoff.json>` сохраняет полный
прежний JSON в файл с правами 0600, а в stdout возвращает путь, SHA256 и ревизию.
Исполнитель получает полный result; критерии, источники, trace_context,
delivery_id и проверки зависимостей не сокращаются. Без --output прежний
вывод/API сохраняется; managed-сборка и формат реестра не меняются.

Существующие файлы, входы, пути результатов и реестр не перезаписываются.
Симлинки отклоняются. Публикация файла предшествует фиксации dispatching:
после прерывания наличие файла требует проверки реестра и не разрешает запуск.
Нельзя повторять prepare при неизвестном исходе. Состояния, исторические
архивы и контрольные суммы не мигрируются.

`read_qa_instructions.py` позволяет перечислить заголовки, прочитать выбранные
разделы документа вместе со вступлением или только frontmatter роли для
маршрутизации. Полное тело роли по-прежнему передаётся исполнителю. Ошибки
заголовков не приводят к молчаливому пропуску инструкций. Координатор выбирает
применимые разделы и запрашивает нужные поля первичных источников; doctor
продолжает локально сверять полный манифест, не выводя его в историю целиком.

Сохранённое локальное измерение явного текста до добавления гейтов отказов
(Unicode-символы; это предыдущий снимок инструкций, не их текущий размер):

Для документов сравнивались полный текст и выбранные разделы одного снимка
со вступлением. Разделы соответствуют таблице GIGACODE_OPTIMIZATION;
для TASK_ACCEPTANCE использованы «Согласованные критерии», «Готовность для
исполнения и информационный контекст», «Оценка критериев».
Назначение измерялось на копии examples/task-exchange/assignment.json с ролью
qa-test-plan-writer, stage=planning и локальными входом/результатом во временной
папке. Полный JSON сохранённого файла сравнивался с квитанцией того же prepare;
длина временного пути влияет на числа. Полный handoff и роль исполнителя не
сокращались. Таблица не учитывает чтение новой инструкции и весь QA-маршрут.

Схемы tools, память клиента, его hooks и интерактивный usage здесь не измеряются.
Снижение объёма stdout не доказывает экономию токенов, времени или качество модели.
