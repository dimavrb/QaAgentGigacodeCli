# Обновление QA-пакета 2.3.17

После установки один раз настройте alias:

```bash
alias qa-start='python3 .qa-agent/package/scripts/qa_start.py'
```

Затем запускайте `qa-start` из корня приложения. Он сам проверяет новую версию
перед открытием GIGACODE: официальный main → успешный CI точного коммита →
проверка состава/импорта → установка всего комплекта → запуск нового launcher и CLI.
QA MCP-сервер не используется. Major-переходы требуют ручного выбора нового выпуска.

При отсутствии сети/Git или неподтверждённом CI запускается прежний проверенный пакет.
При незавершённых QA-задачах/планах или открытой CLI-сессии обновление откладывается;
можно продолжать текущую работу. Конфликт, повреждение или pending установки
останавливает запуск с диагностикой. Нет автоматического --force или переписывания
исторических хешей. Контекст приложения и доказательства сохраняются.

`qa-start --no-update` пропускает сетевую проверку. `qa-start --update-only` применяет
доступное обновление без запуска GIGACODE. Прямой длинный эквивалент:
`python3 .qa-agent/package/scripts/qa_start.py`.

Для перехода с 2.3.13 один раз обновите пакет терминальным qa_install.py из
нового выпуска между сессиями; прежний launcher ещё не умеет этот проектный режим.
Ручная установка и восстановление — [PROJECT_INSTALLATION.md](PROJECT_INSTALLATION.md).
Согласованный комплект можно коммитить одним PR. На других checkout выполняйте
Git pull между сессиями и проверяйте doctor; состояние QA-задач не переносится Git.
