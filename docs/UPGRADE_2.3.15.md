# Обновление до 2.3.15

Завершите активные назначения/managed-планы и закройте сессии GIGACODE.
Обновляйте полный комплект, сохранив локальные адаптации и доказательства.
Исторические реестры, frozen-планы, архивы и хеши не переписываются.

С проектным launcher версии 2.3.14+ запустите `qa-start --update-only` после
публикации выпуска и успешного CI точного коммита. Для ручного обновления
получите проверенную копию 2.3.15, затем выполните preview и установку:

```bash
python3 /path/to/qa-agent-2.3.15/scripts/qa_install.py --project-root /path/to/app
python3 /path/to/qa-agent-2.3.15/scripts/qa_install.py --project-root /path/to/app --apply
```

При конфликтах рассмотрите адаптации; не обходите pending и блокировки.
Выполните локальный doctor, откройте новую сессию и проверьте роли, навыки,
команды и memory. Для прежнего глобального extension порядок перехода
сохранён в [UPGRADE_2.3.14.md](UPGRADE_2.3.14.md).

Новые передачи координатора используйте с `prepare --output` по TASK_EXCHANGE.
Существующие вызовы без флага работают по прежнему контракту. Путь к файлу
не заменяет передачу полного result bare-исполнителю; используйте его сборщик.
Чтение разделов и метаданных роли — [GIGACODE_OPTIMIZATION.md](GIGACODE_OPTIMIZATION.md).
Версия не меняет настройки MCP, авторизацию и память установленного клиента.

Перед новыми назначениями координатор применяет COORDINATION_SAFETY.md и
сохраняет preflight вне поставки. Полные тексты 14 ролей обновляются вместе
с пакетом; локальные адаптации рассматриваются по правилам обновления, без
force. Для managed нужны новые планы с новыми хешами инструкций; старые
frozen-планы/реестры не мигрируются. Новый guard не устанавливается Markdown:
проверь фактические capabilities своей сборки, передавай запрещённые роли
валидатор/SHA256 координатору. Отсутствие метаданных сессии остаётся ограничением
приёмки владельца. Встроенный технический семафор тяжёлых ролей не добавлен.
