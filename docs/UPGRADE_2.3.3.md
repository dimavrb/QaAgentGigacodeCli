# Обновление до 2.3.3

1. Остановите активные назначения и проверьте внешние действия/readback.
   Обновите пакет целиком по [EXTENSIONS.md](EXTENSIONS.md), сохранив личную
   конфигурацию, реестры и доказательства вне поставки. Сверьте VERSION и
   gigacode-extension.json: 2.3.3.
2. Откройте новую сессию, проверьте qa_package_info, `/qa:init` и `/qa:doctor`.
   Новые managed-планы готовьте с актуальными инструкциями; старые хеши и
   принятые отчёты не переписывайте.
3. Если прежний автор был принят, но затем получил принятое blocking-ревью,
   готовьте исправление под новым request_id и отдельным result_path. Прежний
   checkpoint больше не разрешает следующий переход. Замечания передавайте
   как context или отдельный feedback; другой passing verdict прежней версии
   не снимает блокировку. Для нового плана учитывайте уже выполненные действия.
4. Для незаписанных оценок scenario_execution повторите assess с актуальной
   expected-revision и фактическим решением. failed/unknown не закрывают
   обязательное исполнение; not_applicable требует принятое доказательство.

Миграция JSON и пересчёт исторических хешей не требуются. Установка и локальные
тесты не подтверждают живой runtime и не разрешают публикацию или push.
