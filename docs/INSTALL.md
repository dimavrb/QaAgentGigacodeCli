# Установка QA-пакета 2.3.16

Основной способ — [проектная установка](PROJECT_INSTALLATION.md): обычные файлы
в `.qa-agent/package/`, профиль в `.gigacode/`, без собственного QA MCP-сервера.
Нужны Python 3.10+, настроенный GIGACODE и macOS/Linux или WSL.

Если QA extension уже подключён, выполните `/qa:init` в GIGACODE из папки
приложения. Команда сама подготовит проектный исходник и выполнит первую
установку, затем init/doctor. Нужны Git, сеть и shell-инструмент.
После установки откройте новую сессию для загрузки проектного профиля.
Повтор /qa:init не меняет установленную версию.

При отсутствии extension/команды или для обновления между сессиями остаётся
терминальный способ:

Из обычного терминала, до запуска GIGACODE:

```bash
python3 /path/to/qa-agent/scripts/qa_install.py --project-root /path/to/app
python3 /path/to/qa-agent/scripts/qa_install.py --project-root /path/to/app --apply
```

Просмотрите план; при конфликте установщик сохраняет прежний комплект.
В приложении выполните `/qa:init`, `/qa:doctor`, проверьте `/agents manage`,
`/skills`, `/help` и `/memory`. Затем начните QA-задачу по требованиям.
Для первого запуска можно использовать
`python3 .qa-agent/package/scripts/qa_start.py --project-root .` из корня приложения.

Пакет, профиль и install.json можно хранить вместе в Git. Локальные состояния,
доказательства, настройки доступа и секреты исключаются из поставки и Git.
Файлы расширения в корне пакета нужны для совместимости discovery, но native
install сам по себе не создаёт проектную копию Python. Переход с глобального
расширения, обновление и восстановление описаны в PROJECT_INSTALLATION.md.

После подключения настройте контекст приложения по examples/qa-only/APP_CONTEXT.template.md,
внешние системы — по применимым разделам SETUP_AND_UPDATE.md и BROWSER_PROFILES.md.
Локальный doctor не подтверждает живой запуск модели и доступность продуктовых систем.
