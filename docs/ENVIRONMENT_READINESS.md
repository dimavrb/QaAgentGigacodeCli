# Готовность стенда по админгайду

Стенд готов, когда подтверждено выполнение **всех пунктов переданного
админгайда** для назначенного стенда и версии. Список доступных возможностей
и успешный код команды не заменяют выполнение пунктов.

## Назначение координатора

До запуска настройщика координатор сохраняет environment_assignment — JSON
снимок полного списка пунктов. Он читает исходный гайд и проверяет полноту
списка содержательно; Python не извлекает все обязательства из свободного текста.
Исполнитель не выбирает подмножество и не редактирует этот снимок.

admin_guide.path указывает на локальный текст UTF-8 (например, Markdown).
Для другого формата координатор сначала предоставляет проверенный полный
текстовый снимок, сохраняя ссылку на первоисточник. Автоматическое извлечение
из PDF/Word или внешних систем этим валидатором не выполняется.

Пример снимка:

```json
{
  "schema_version": 1,
  "task_id": "QA-42",
  "environment_id": "test",
  "product_version": "42",
  "created_at": "2026-10-15T10:00:00+03:00",
  "admin_guide": {"path": "admin-guide.md", "sha256": "SHA256 исходного файла"},
  "scenario_ids": ["TC-1"],
  "points": [{"point_id": "ADM-1", "quote": "Точная цитата пункта гайда",
              "expected_result": "Наблюдаемый результат по гайду", "scenario_ids": ["TC-1"]}]
}
```

В назначении qa-test-env-configurator передай абсолютный environment_assignment.
Реестр автоматически включает снимок и исходный гайд в замороженные inputs,
проверяет task_id и полный scenario_ids. При отсутствии гайда/списка разрешён
только blocked с конкретным недостающим источником. Не придумывай содержание
гайда и не выполняй неподтверждённые команды. Изменение гайда/версии/списка
требует нового снимка и назначения; исторические хеши не переписываются.

## Результат каждого пункта

Payload сохраняет environment_id, product_version, verified_capabilities,
limitations, environment_assignment_sha256 и guide_checks. Каждый элемент:

```json
{"point_id":"ADM-1", "status":"passed", "actions":["Фактически выполненное действие"],
 "actual_result":"Наблюдаемый результат", "observed_at":"2026-10-15T10:05:00+03:00",
 "evidence":["evidence/ADM-1.txt"]}
```

Допустимы passed, failed, blocked, not_run. Все ID исходного списка присутствуют
ровно один раз. passed/failed требуют фактические действия, время наблюдения
не раньше снимка и доступное локальное доказательство. Чужой стенд/версия,
пропущенный пункт, ссылка на сам гайд/снимок/отчёт вместо наблюдения запрещены.
Гайд задаёт ожидаемый результат; смысловое соответствие действий и доказательства
этому результату проверяет координатор или назначенный независимый reviewer.

environment_ready разрешён только при passed всех пунктов. Если не все пункты
выполнены, полной готовности нет. Для environment_partial готовые сценарии
вычисляются по пунктам, связанным с каждым ID: все их пункты должны быть passed.
Общий пункт связывается со всеми сценариями. Нельзя объявлять готовый subset
при невыполненном общем пункте. Если готового subset нет — blocked. Для стенда
без scenario_ids проверяется весь гайд; неполный результат остаётся blocked.

## Передача и приёмка

Новые назначения реестра требуют этот протокол для ready/partial; без гайда
они могут вернуть blocked. submit, review, готовые зависимости, assessment,
finish и восстановление checkpoint повторно проверяют доказательства/хеши.
Вложенные evidence хешируются даже без дублирования в artifacts.
В bare-контекст настройщика автоматически входят эта инструкция и все inputs.

Для прямого CLI используй --require-environment-checks и --environment-assignment
вместе с validate_qa_result.py, ожидаемыми task/request/agent и всеми --scenario-id.
Проверка старых сообщений без новых полей остаётся режимом структурного аудита;
она не даёт готовности новому назначению реестра: такая зависимость доступна
только как context до новой проверки. Старые реестры/архивы не мигрируют
подменой хешей или добавлением выдуманных наблюдений.

## HTML-отчёт и оставшиеся вопросы

После содержательного принятия environment_ready/environment_partial/blocked
реестр автоматически создаёт `<result>.environment.html` и сохраняет ссылку в
presentation. Координатор открывает страницу в доступной HTML-панели/браузере
и возвращает пользователю ссылку вместе с исходным JSON. HTML содержит статус
стенда и версию, результат настройки, каждый пункт/ожидание/действие/наблюдение,
время и ссылки на доказательства, блокеры, ограничения и оставшиеся вопросы.
Отклонённый результат не публикуется как итоговая страница.

В payload.open_questions укажи список объектов либо явно []:

```json
{"question_id":"Q-API", "question":"Какой адрес API использовать?", "status":"open",
 "blocking":true, "point_ids":["ADM-2"], "scenario_ids":["TC-1"],
 "context":"Проверка пункта ADM-2 ожидает подтверждённый адрес"}
```

Для resolved обязательны resolution и decision_source; такие вопросы не входят
в оставшиеся. Открытый blocking-вопрос должен ссылаться на невыполненные пункты
и исключает полную готовность. Вопрос без влияния на готовность имеет blocking=false.
Отсутствующее поле в старом отчёте показывается как «не указано», а не «вопросов нет».
Ответы при необходимости собираются штатной формой по QUESTIONS_UI.md; эта
страница фиксирует вопросы принятой версии и сама не изменяет реестр ответов.

presentation.status=ready означает готовность HTML-документа. Статус стенда
environment_partial/blocked остаётся виден и не меняется. Если построение не
удалось, presentation.status=needs_attention содержит причину; принятие JSON
сохраняется. Повтор проверяет исходные хеши и не перезаписывает чужой файл.
Пересборка принятого отчёта:

```bash
python3 scripts/build_environment_html.py --state /absolute/task.json --request-id env-1
```

Страница самостоятельная, без внешних скриптов и сетевых зависимостей. Для её
переноса вместе с рабочими ссылками сохраняйте доступность локальных источников
и доказательств. Реальные секреты не включаются в публикуемые материалы.
