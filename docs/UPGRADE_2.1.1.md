# Переход с Qwen 2.1 на GIGACODE 2.1.1

Это смена среды исполнения, не доказательство улучшения качества модели.
Сохраните исходный пакет Qwen, архив 2.1 и рабочие состояния до перехода.

- `QWEN.md` заменён на `GIGACODE.md`; общие инструкции — `docs/COORDINATOR.md`.
- `.qwen/` заменена на `.gigacode/`: роли, skills, `/qa`, MCP-профиль.
- `APP_QWEN.md` при новой установке заменён на нейтральный `APP_COORDINATOR.md`.
- CLI-параметр runner/benchmark/grader теперь `--cli`; настройки — `qa-runtime.json`.
- Новые метрики используют backend/cli_version/cli_executable_sha256. Старые
  qwen-поля сохраняют происхождение старых измерений; смешивать runtime нельзя.
- Управляемый адаптер по умолчанию — gigacode; старый `kind=qwen` требует явно
  составленного нового плана. Проверьте readback записей до продолжения.
- Qwen tools.eager не переносится в GIGACODE без отдельной проверки.

Не заменяйте строки внутри старых registry, benchmark, manifest, journals и ZIP:
это нарушает hashes и приписывает наблюдения другому исполнителю. Открытые задачи
сохраните для аудита; новый запуск выполняйте с новыми request_id и согласованным
объёмом после сверки внешнего состояния.

Установите GIGACODE и настройте собственную модель/auth. Выполните инструкции
[INSTALL.md](INSTALL.md), локальные тесты и preflight [RUNTIMES.md](RUNTIMES.md).
Проверьте интерактивную загрузку ролей/skills/команды, ограничения CLI и один
реальный QA-маршрут. До этого live-совместимость остаётся непроверенной.
