# Обновление до 2.3.6

1. Завершите активные назначения, сохраните runtime-состояние вне поставки и
   обновите пакет целиком по EXTENSIONS.md. Сверьте VERSION и manifest: 2.3.6.
2. В новой сессии проверьте qa_package_info, `/qa:init` и `/qa:doctor`.
   Для изменённых инструкций создайте новый managed-план с актуальными хешами.
3. Для новых назначений qa-test-data-builder координатор готовит data_assignment
   по DATA_READINESS.md с полным списком условий и реальным окном использования.
   Передавайте файл через поле назначения, а не только через текст goal.
4. Исполнитель возвращает структурированные verified_properties, product_version,
   data_assignment_sha256 и data_state. Проверки должны наблюдать фактический набор;
   рецепт без проверки и очищенные фикстуры не считаются готовыми.
5. До зависимого запуска проверьте готовность нужных сценариев и доступность
   набора, после завершения — очистку собственных ресурсов. Истёкшее окно требует
   нового request_id и свежих наблюдений. Не продлевайте принятый expires_at.

Исторические JSON, реестры и hashes сохраняются без пересчёта и выдуманных
наблюдений. Старый формат валидируется структурно обычным CLI; для диагностики
используйте dependency_modes=context. Для истёкшего нового отчёта доступен
--data-context-only вместе с --data-assignment; этот режим не даёт готовности.
Новые назначения не могут отключить data_checks_required, отсутствие scope
разрешает только blocked. Для работы по старому ready-источнику нужно новое
назначение и предметная проверка. Автоматического удаления/создания данных нет.
