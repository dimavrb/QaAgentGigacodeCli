# QA-пакет 2.1.3 — ручные кейсы через GitVerse и Jenkins

Дата: 2026-10-13. Профиль GIGACODE CLI: 14 ролей, 5 skills и `/qa`.
Требования пакета сохранены: Python 3.10+, стандартная библиотека, macOS/Linux
или WSL. Java/JUnit остаётся стеком продуктовых автотестов; генератор ручных
кейсов не требует Java.

## Изменения

- `scripts/build_manual_allure.py` преобразует ручные JSON-кейсы в Allure-файлы
  без выполнения тестов и без ложного Passed. Идентичность определяется
  namespace и локальным ID; существующие карточки связываются через scoped ID-карту.
- `examples/testops-jenkins/` содержит каталоги-примеры и два Jenkinsfile:
  preview веток без загрузки и публикацию основной ветки по вебхуку GitVerse.
  Публикация выключена до успешного пилота.
- Ошибки JSON, дубли, символические ссылки, неоднозначные ID и старые результаты
  не должны приводить к молчаливой потере кейсов или повторной отправке файлов.
- `docs/TESTOPS_JENKINS.md` определяет сбор параметров при подготовке реальной
  инфраструктуры. `AGENTS.md` требует повышения версии при коммите поставки.

## Проверки

Локальный набор: 598 тестов, включая 16 проверок генератора. Дополнительно
проверяются пример данных, shell-команды Jenkins-шаблонов и ZIP manifest.

```bash
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s examples/test-data -v
python3 scripts/package_agent.py --output-dir dist/release-2.1.3 --date 2026-10-13
python3 scripts/package_agent.py --verify dist/release-2.1.3/qa-agent-2.1.3.zip
```

## Пределы и обновление

Живые GIGACODE, GitVerse payload, Jenkins-плагин и импорт вашей сборкой ТестОпс
требуют отдельной проверки. Allure-путь создаёт запуск, а не чистое API-обновление
карточек. Ожидания представлены вложенными шагами, предусловия — HTML-описанием;
нативные секции ТестОпс этим форматом не подтверждены.
