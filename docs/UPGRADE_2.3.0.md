# Обновление до 2.3.0 с 2.2.x

1. Завершите активную работу и сохраните прежнюю поставку/адаптации. Если есть
   pending старого updater, сначала выясните состояние и завершите прежнюю
   активацию: 2.3.0 не создаёт прошлый backup задним числом.
2. Для первичного принятия защиты обновите весь локальный clone и расширение
   вручную штатным менеджером по EXTENSIONS.md. Не подменяйте registry. Проверьте
   VERSION и gigacode-extension.json = 2.3.0, Python 3.10+, Git 2.36+.
3. В новой сессии выполните `/qa:init`, `/qa:doctor`, `/qa:tasks`. Контекст и
   исторические артефакты сохраняются. При переносе пути сначала покажите старый/
   новый binding; CLI fallback требует digest из первой ошибки:
   `--rebind --expected-binding-sha256 <SHA-256>`. MCP использует прежний двухшаговый режим.
4. Дальнейшие обновления через qa-start принимаются после CI точного SHA и
   полной предвалидации. Если CI не подтверждён, используется прежняя версия.
   После первого защищённого обновления проверьте recovery helper/snapshot по
   [UPDATE_SAFETY.md](UPDATE_SAFETY.md).
5. В отдельном тестовом профиле выполните живой update/rollback, проверьте
   версии файлов, registry менеджера, контекст, кейсы, auth и saved task IDs.
   Пользовательский профиль и production-инсталляцию для этого пилота не используйте.

Уже установленный helper не заменяется автоматически: его checksum/формат
сохраняются для независимого восстановления. Снимки старых выпусков не
переписываются. При незавершённом rollback вызывайте внешний helper; повреждённые
backup/Git и посторонние изменения требуют ручного разбора без слепого reset.
Новые инструкции применяйте к новым managed-планам, сохраняя прежние hashes.
