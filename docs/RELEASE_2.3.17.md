# QA-пакет 2.3.17 — тесты и актуальные eval-задания

70 тестов из test_first_package/test_second_package разнесены по предметным
модулям task_acceptance, benchmark_execution, agent_trace, managed_execution,
action_gateway, process_control. Тестовые методы и assertions сохранены;
перенос проверен сравнением AST. UpdateFixture отделена от AutoUpdateTests:
проверки hardening больше не создают и не запускают setUp другого теста.
Gateway-политика и программный reasoning CLI имеют отдельные общие фикстуры.
Последний явно имеет measurement_kind=fixture, без выдачи за живой замер.

Новый regression-suite содержит 17 синтетических задач/68 критериев. Он проверяет
различающие данные, краткость без потери условий, свежесть наблюдения и границы
вывода, положительные кейсы, восстановление/владельцев, анкету и ограничения tools.
Добавлены задания для прежних непредставленных ролей. Вместе с suite/quality/profile
все 14 ролей имеют хотя бы одно reasoning-задание; это не полнота их поведения.
Старые suite/prompts и исторические протоколы/хеши не менялись.

Eval-runner поддерживает явные test_type и instruction_paths. Manual-case роль
получает индекс и один валидный пример нужного канала; предметные Markdown из docs
добавляются явно. Рубрика не включается в system/prompt. Пустые prompts, неизвестные
роли/каналы, внешние instruction paths и выход prompt через symlink отклоняются до CLI.
Reasoning-контекст выбирает применимые разделы и сохраняет полные JSON-примеры,
не загружая координационный workflow всем ролям. Исправлен риск превышения
Linux-лимита одного argv: system stored-value уменьшен с 211954 до 121411 байт
UTF-8. Добавлена проверка размера для всех поставляемых suite; экономия токенов
и качество этим не измерены. Тест сравнимости A/B теперь проверяет конкретный
отказ изменения общей инструкции при согласованных локальных fixture-хешах.
Хеш prompt остаётся частью suite fingerprint, а старое ревью не подтверждает новую
редакцию. Прежние suite без новых полей остаются совместимыми.

Новые локальные проверки проходят полный capture/грейдинг-копию/CLI-сводку без
смыслового self-grade, ловят изменённую копию, чужую session и подставленные числа.
Для анкет закреплены отсутствие записи answers в build и сохранение общего
комментария при всех deferred. Карта тестов и пределы полноты —
[tests/README.md](../tests/README.md), задания —
[REGRESSION.md](../examples/benchmark/REGRESSION.md).

Живой GIGACODE в среде аудита отсутствует; качество модели, токены, внешние
интеграции и устранение 429 не измерены. Процент покрытия строк/ветвей не измерен.
Локальный проход не заявляется как результат матрицы CI Linux/macOS.
