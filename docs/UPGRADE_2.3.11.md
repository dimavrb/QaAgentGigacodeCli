# Обновление до 2.3.11

1. Сохраните текущую поставку, проектные роли, адаптации, binding и runtime
   вне заменяемых каталогов. Завершите активные назначения и сессии. Обновите
   пакет по EXTENSIONS.md, при требовании uninstall — штатной переустановкой.
   Существующий native pending сначала завершите на его подготовленном commit;
   журналы, snapshots и исторические hashes не удаляйте.
2. Сверьте VERSION и gigacode-extension.json: 2.3.11. Освежите привязку через
   `/qa:init` либо абсолютный `qa_project.py init --project-root ...` из установленного
   пакета. Init добавляет игнорирование локальной истории ролей и сохраняет контекст.
3. Для существующих проектных копий из 2.3.10 выполните preview и явный
   `qa_project_agents.py --project-root ... --apply`. Идентичные файлы принимаются
   в историю; отличающиеся без известной базы сохраняются как `unknown_baseline`.
   Новые отсутствующие роли добавляются. Не подменяйте неизвестную базу догадкой.
4. Рассмотрите конфликты по PROJECT_AGENT_UPDATES.md. После ручного сравнения/
   объединения выполните новый preview и `--accept-local` с актуальными двумя
   хешами либо приведите файл к точной новой версии. Удалённая локально роль
   требует `--restore`; адаптированную устаревшую роль сохраните вне discovery.
5. Дальше запускайте `qa-start`: управляемые роли синхронизируются до новой
   сессии, конфликты блокируют запуск. `--no-update` не обходит конфликт ролей.
   При прямом `gigacode` запускайте sync отдельно. Проекты без проектных копий
   не подключаются к этому режиму автоматически.
6. Проверьте `/qa:doctor`, новую сессию, `/agents manage`, вызов конкретной роли
   и возврат координатору. После изменения инструкций создайте новый managed-план.
   Выполните локальные проверки из RELEASE_2.3.11.md.

После прерывания sync повторите `--apply`, сохранив реестр, blobs и pending.
После отката между выпусками с поддержкой истории синхронизируйте роли тем же
порядком. Для 2.3.10 и ниже восстановите согласованный снимок пакета, ролей и
прежнего состояния, сохранив текущую историю отдельно. Старые утилиты не применяйте поверх
незавершённой транзакции. При повреждении истории сначала восстановите её
проверенную копию; не удаляйте реестр ради принудительной замены ролей.
