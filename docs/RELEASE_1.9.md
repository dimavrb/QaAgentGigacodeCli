# Поставка QA-агента 1.9

Дата: **2026-10-08**. Архив: `qa-agent-1.9.zip`, checksum: `qa-agent-1.9.zip.sha256`. Внутренний PACKAGE_MANIFEST.json содержит версии, дату, размеры и SHA-256 всех файлов. Специализированных ролей — **11**, навыков — **2**, команда — `/qa`.

## Изменения относительно 1.8

- HTML-форма вопросов: список со стабильными ID, ответы на каждый вопрос, одна общая отправка, черновик и явное «пока не знаю». Локальный сервер сохраняет ответы атомарно; автономный файл позволяет копирование/JSON. Ответ связан с ревизией пакета, повторная отправка неизменённого ответа не дублируется.
- Единый task-state: назначения, зависимости, владельцы, резервирование передачи, защита ревизии между процессами и устойчивые события готовности. Полный валидатор проверяет сохранённый результат; зависимая передача требует содержательного принятия и неизменных источников/доказательств. Форма и standalone-runner подключаются через `--task-state`.
- Самопроверка всех 11 исполнителей: соответствие назначению, доказательства, согласованность и предметный риск роли. `self_review` содержит короткие выводы, ссылки, выполненные исправления и оставшиеся риски. Новые назначения реестра и новые запуски runner отклоняют отсутствие/невалидность самопроверки; независимое ревью сохраняется.

Все возможности 1.8, включая общий Playwright-пул, заглушки, данные, журнал, расследование и отчётность, сохраняются. Новых специализированных ролей и подключений не добавлено.

## Установка и совместимость

Переход — UPGRADE_1.9.md и UPDATE.md; первая установка — INSTALL.md, IMPORT_INTO_APP.md и SETUP_AND_UPDATE.md. Рядом с ZIP находятся их копии с суффиксом 1.9, RELEASE_1.9.md и внешний протокол VALIDATION_1.9.json. Архивы и инструкции прошлых поставок сохранены для отката.

Python **3.10+**, стандартная библиотека; реестр с flock и отдельный runner требуют macOS/Linux/WSL. Playwright MCP остаётся **0.0.83**. Task-state, browser_pool, пользовательские ответы, журналы и доказательства хранятся вне заменяемого пакета. ZIP не содержит Git/IDE/cache, dist, runtime-реестров и пользовательских данных.

Старые сохранённые QA-отчёты и уже зарегистрированные назначения без self_review_required совместимы. Новые assign получают self_review_required=true, новый standalone-runner требует self_review. Исторические принятые результаты не переписываются. Формат самопроверки не подтверждает правильность вывода автора: координатор отдельно оценивает содержание и обязательные ограничения.

Очередь событий не пробуждает завершённый Qwen-чат. Реестр не является сетевым транспортом между хостами: исполнители должны видеть одни и те же файлы и пути. Передача агенту остаётся задачей координатора через доступный механизм Qwen. Локальная форма должна оставаться запущенной для сохранения/уведомления.

## Проверки поставки

Из корня распакованного пакета:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_test_cases.py --input examples/test-cases.json
python3 -m unittest discover -s examples/test-data -v
python3 scripts/validate_qa_result.py --input examples/task-exchange/result.json --task-id QA-EXCHANGE --request-id QA-EXCHANGE-env-1 --agent qa-test-env-configurator --require-self-review --self-review-assignment examples/task-exchange/assignment.json
python3 scripts/questionnaire.py build --input examples/questions/questions.json --output artifacts/questions/release/questions.html
```

Ожидаются **245 тестов пакета** и один отдельный учебный тест данных. Новые группы: 10 тестов формы, 23 теста реестра, 9 тестов самопроверки; 21 тест runner включает регистрацию результата в реестре и отказ при отсутствии самопроверки. Они используют синтетические материалы и подставной CLI, не проверяют качество ответов модели.

Учебный CLI-цикл init → assign → prepare → submit → review приведён в `examples/task-exchange/README.md`. Выполняйте его в отдельной распакованной копии с новым реестром; ожидается ревизия 5 и accepted после явного содержательного решения. Если удалить self_review, указать несуществующую ссылку либо изменить принятое доказательство, передача отклоняется. Новые исправления после submit требуют нового назначения.

Для прежних возможностей используйте команды RELEASE_1.8.md (пул), RELEASE_1.7.md (заглушки) и RELEASE_1.6.md (отчёты, расследование, журнал и данные). Исторические числа тестов относятся к своим версиям; для 1.9 актуальны 245. Полный текущий набор включает их регрессии.

Проверка ZIP: `python3 scripts/package_agent.py --verify /absolute/path/qa-agent-1.9.zip`. Checksum проверяется соседним .sha256. Протокол конкретного ZIP фиксирует тесты исходников и распакованной копии, проверку манифеста, соответствие всех файлов исходникам, исключение runtime-данных и результаты учебных CLI. Сам внешний VALIDATION_1.9.json не включается в ZIP: он содержит checksum уже построенного архива.

## Проверка в рабочем окружении

После установки проверьте новую сессию Qwen, применимые MCP и чтение новых стандартов из подключённых копий ролей. На разрешённой небольшой задаче оцените реальные вопросы/общую отправку, обработку события координатором и качество self_review. Для модели сравнивайте одинаковые задачи: ошибки и возвраты ревью, пропущенные ограничения, время и токены. Сборка не подтверждает экономию или прирост качества. Живые Qwen, Playwright/sbermock, продуктовый CI и Allure при упаковке не запускаются.
