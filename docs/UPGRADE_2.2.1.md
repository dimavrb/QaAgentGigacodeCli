# Обновление с 2.2.0 до 2.2.1

1. Завершите активную сессию, сохраните предыдущую поставку и локальные адаптации.
2. Обновите локальный clone и установленное расширение штатным менеджером по
   [EXTENSIONS.md](EXTENSIONS.md), либо запустите настроенный `qa-start` до сессии.
   Установка принимает локальную папку. Оба файла VERSION/манифеста — `2.2.1`.
3. Откройте новую сессию, выполните `/qa:init`, `/qa:doctor`. В `/help` должны
   быть `/qa:tasks`, `/qa:resume`, в `/mcp` — `qa_tasks_list`, `qa_task_get`
   вместе с тремя прежними инструментами.
4. В продукте выполните `/qa:tasks`, затем `/qa:resume <ID>` для выбранной задачи.
   Подтвердите владельца, точные артефакты и применимость условий перед продолжением.
   Для проверки пустого списка используйте новый отдельный проект; просмотра
   достаточно, создавать реестр без задания не требуется.
5. Для новых задач используйте [TASK_STORAGE.md](TASK_STORAGE.md). Старые пути
   планов, каталогов и расследований остаются прежними. Нестандартный реестр
   передавайте явно: поиск охватывает только `.qa-agent-state/tasks/*/task.json`.

Контекст приложения, auth/MCP, кейсы, результаты и исторические hashes не
переписываются. Игнорируемые локальные реестры не появляются у коллег от Git clone;
общее хранилище исполнения настраивается отдельно. Изменённые инструкции применяйте
к новому managed-плану. При отменённом исполнении чтение задачи не заменяет
явное разрешение resume. Пределы промышленной готовности — RELEASE_2.2.1.md.
