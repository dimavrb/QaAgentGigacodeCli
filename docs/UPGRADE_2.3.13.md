# Обновление до 2.3.13

1. Сохраните адаптации и текущую поставку; завершите активные назначения и managed-планы,
   закройте GIGACODE. Историю, старые пути, подтверждения и хеши не переписывайте.
2. Получите полный проверенный выпуск 2.3.13 в отдельную папку вне приложения.
3. Выполните его `scripts/qa_install.py --project-root /path/to/app` для preview.
   При конфликтах рассмотрите старые копии ролей/навыков и сохраните адаптации.
   Установщик не выбирает между чужим файлом и новой версией автоматически.
4. Повторите команду с --apply. Будут созданы .qa-agent/package, переносимый
   install.json и профиль .gigacode; контекст/настройки и результаты сохраняются.
5. Через штатный менеджер вашей сборки отключите прежний глобальный qa-agent.
   Новый выпуск не содержит QA MCP-сервер; в новой сессии он не должен оставаться
   от прежнего extension. Установщик не редактирует глобальный registry.
6. В корне приложения выполните локальные qa_project.py init и doctor,
   затем проверьте /agents manage, /skills, /help и /memory в новой сессии.
   Удалите дублирующий старый импорт координатора после сохранения адаптаций.
7. Пройдите create → assign → prepare → submit с локальным валидатором → review
   на тестовой задаче, отдельно проверив ограничения вашей сборки GIGACODE.

Проектные файлы коммитьте согласованным комплектом. На других компьютерах
выполняйте git pull между сессиями и затем doctor. Старый project.local.json
остаётся локальным; новый install.json имеет приоритет. Активные старые планы
не мигрируют автоматически. Если обновление прервалось, используйте установщик
из внешней копии выпуска с --recover --apply, затем повторите обновление.
Подробности — [PROJECT_INSTALLATION.md](PROJECT_INSTALLATION.md).
