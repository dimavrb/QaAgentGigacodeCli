# Обновление QA-пакета с 2.1.2 до 2.1.3

Обновление добавляет публикацию ручных JSON-кейсов и правило версионирования.
Формат продуктовых каталогов и контракт GIGACODE runner не меняются.
Реальные URL, ID проектов и credentials для обновления файлов не требуются.

## Порядок

1. Сохраните предыдущий commit/ZIP и локальные адаптации. Остановите активных
   исполнителей; сохраните runtime-состояние и доказательства вне поставки.
2. В Git-копии без незакоммиченных изменений получите текущую основную ветку:

   ```bash
   git switch main
   git pull --ff-only origin main
   cat VERSION
   ```

   Для этого выпуска ожидается `2.1.3`. Для установки из ZIP распакуйте проверенный
   архив в новый каталог по [SETUP_AND_UPDATE.md](SETUP_AND_UPDATE.md).
3. Обновите весь пакет. Если он подключён к приложению, отдельно обновите
   исходную копию `qa-agent/`, роль `qa-test-env-configurator`, подключённые
   роли/skills/команду и адаптированный `APP_COORDINATOR.md` по
   [IMPORT_INTO_APP.md](IMPORT_INTO_APP.md). Сохраните auth, локальные MCP,
   настройки приложения и исходные продуктовые кейсы.
4. Выполните полный набор тестов и CLI preflight по
   [SETUP_AND_UPDATE.md](SETUP_AND_UPDATE.md); проверьте профиль в новой сессии.
   Изменённые инструкции требуют нового managed-плана.
5. Для ручных кейсов изучите [пример Jenkins](../examples/testops-jenkins/README.md).
   Копирование шаблонов не подключает реальные системы. При поручении подготовить
   инфраструктуру агент собирает параметры по [TESTOPS_JENKINS.md](TESTOPS_JENKINS.md).

## Уже использовали предварительный коммит `c31fa25`

Этот коммит содержал генератор и Jenkins-шаблоны под номером 2.1.2. В 2.1.3
их поведение и идентичность кейсов сохраняются; повторно публиковать каталог
только из-за смены номера версии не нужно. Новые инструкции и описание выпуска
обновляются вместе с остальным пакетом.

При переходе с более раннего пакета сначала учтите
[миграцию на GIGACODE](UPGRADE_2.1.2.md). Исторические архивы, hashes, ID-карты
и журналы не переписывайте. Для отката восстановите предыдущую поставку и
локальные адаптации, сохраняя актуальное состояние внешних действий.
