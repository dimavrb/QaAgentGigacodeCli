# Ревью qa-stub-builder — 2026-10-07

Ревью выявило ложную готовность в нескольких локальных проверках. Дефекты воспроизведены на синтетическом примере, исправления внесены в исходники. Живой MCP sbermock в этой сессии недоступен.

| Проблема | До исправления | Исправление |
| --- | --- | --- |
| P1: ожидание выбирает само доказательство | Если заменить expected и actual на неверный REST-ответ, результат оставался valid | Определение/input/expected фиксируются в назначении координатора. CLI принимает его внешним параметром; артефакты связаны digest |
| P1: лишнее условие matcher игнорируется | Добавление must_be_admin внутри request.body не меняло принятие | Заданные поведенческие ветки конфигурации сравниваются целиком, с учётом типов; дополнительные корневые метаданные оценивает координатор |
| P1: старое наблюдение засчитывается | Проба с observed_at=1999 принималась при текущем request_id | Границы issued/prepared/resolved/verification_started/readback/probe; пробы после всех мутаций, Kafka-capture после readback |
| P2: некорректная операция вызывает исключение | operation=[] приводил к TypeError вместо списка ошибок | Тип и разрешённый объём валидируются до обращения к таблице cleanup |
| P1: создание может повлечь неназначенный Kafka-трафик | Нет отдельного результата для созданной, но runtime-непроверенной конфигурации | configure_only без публикаций/проб и stubs_configured отдельно от execution readiness; в verify только назначенные пробы |
| P1: восстановление опирается на произвольный объект | previous_definition не привязан к фактическому снимку до изменения | Для update — назначенный ID, snapshot/hash/контекст/время и проверка конфликтов перед реальным восстановлением |
| P2: привязка к имени соединения | mcp_server должен был буквально равняться sbermock | provider=sbermock, конкретный alias/server из внешнего назначения |
| P2: чтение и hash относятся к разным версиям файла | При изменении профиля между чтениями можно проверить hash другого содержимого | Разбор JSON и hash вычисляются из одних прочитанных байтов; регрессия моделирует смену файла |

Обнаружен и закрыт перенос ранней пробы через позднюю мутацию: verification_started_at фиксируется после всех изменений, readback/пробы требуют этой границы. Добавлена отдельная проверка намерения до MCP через validate_stub_assignment.py.

Дополнительно: Kafka-проверки требуют разных корреляций проб, позиции и временного окна; пустое expected.body не допускает произвольный body; JSON с повторными ключами/NaN/Infinity отклоняется. Сохраняются частичная готовность и все зависимости общей непроверенной заглушки.

Этап stubs_plan_ready позволяет специалисту изучить реальные MCP-схемы без мутаций. Координатор оценивает намерение; при готовом зафиксированном назначении лишний этап не нужен. Definitions и probe-планы передаются артефактами, подробный стандарт читается только по необходимости.

Границы проверки: hashes/метки времени не доказывают истинность наблюдений, актуальное соединение, владение или семантику контракта. Координатор читает безопасные первичные материалы. Гонка при очистке требует фактического conditional update/защиты либо блокера; локальная схема сама её не устраняет. Полный end-to-end продукт с реальным сервисом не проверялся.

Проверки: 178 тестов пакета прошли, включая 27 проверок контракта заглушек. CLI успешно проверил назначение до MCP и три примера: черновик, настройку без проб, полную проверку. configure_only отклоняет пробные артефакты даже у заблокированной записи. Примеры в examples/stubs полностью синтетические и не являются API-документацией sbermock. Исправления включены в поставку 1.7. ZIP 1.6 сохранён без изменений для отката.
