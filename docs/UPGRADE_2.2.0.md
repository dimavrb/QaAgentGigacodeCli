# Обновление с 2.1.5 до 2.2.0

1. Завершите активную QA-сессию и сохраните предыдущую поставку/адаптации.
2. При настроенном `qa-start` запустите следующую сессию через него:
   источник и установленный пакет обновятся до открытия CLI.
   Для ручного обновления выполните `git pull --ff-only origin main` в локальном
   clone, затем `gigacode extensions update qa-agent`. Перед install передаётся
   локальная папка, не Git URL — см. [EXTENSIONS.md](EXTENSIONS.md).
3. Сверьте `VERSION` и `gigacode-extension.json`: оба должны содержать `2.2.0`.
   Откройте новую сессию, чтобы MCP-сервер загрузил новый диспетчер и список tools.
4. В `/mcp` проверьте `qa_package_info`, `qa_project_init`, `qa_project_doctor`.
   Выполните `/qa:init`, `/qa:doctor`; используйте абсолютный путь продукта.
   При том же installed path обновляется версия привязки; контекст сохраняется.
5. При смене installed path сначала вызовите init без `rebind`. Покажите
   пользователю старый/новый пути и установите причину; только для разрешённого
   переноса вторым вызовом той же MCP-сессии передайте `rebind=true`.
   После перезапуска MCP или изменения путей повторите первый шаг.

`needs_attention` — результат диагностики; исправления выполняются отдельным
действием. `isError` содержит `QA project error: …`. CLI fallback остаётся
для недоступных tools, но не для обхода отказа MCP. Контекст приложения, кейсы,
исторические hashes/журналы и внешние настройки при обновлении сохраняются.
Новые инструкции применяйте к новому managed-плану. Пилот на живой сборке
GIGACODE нужен для проверки регистрации и вызова инструментов.
