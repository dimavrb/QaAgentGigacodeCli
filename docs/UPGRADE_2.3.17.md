# Обновление до 2.3.17

Завершите активные QA-назначения и managed-планы, закройте сессии GIGACODE.
Обновляйте полный комплект с сохранением локальных адаптаций и доказательств.
После публикации и успешного CI точного коммита проектный launcher 2.3.14+
может применить выпуск командой `qa-start --update-only`.

Для ручного обновления получите проверенную копию 2.3.17, выполните preview,
рассмотрите конфликты, затем примените:

```bash
python3 /path/to/qa-agent-2.3.17/scripts/qa_install.py --project-root /path/to/app
python3 /path/to/qa-agent-2.3.17/scripts/qa_install.py --project-root /path/to/app --apply
```

Запустите локальный doctor и откройте новую сессию. Для managed-работы нужны
новые планы с текущими хешами; старые реестры и результаты не мигрируются.
Форматы продуктового каталога/результата не изменены.

Для локальной разработки используйте предметные модули из tests/README.md
вместо test_first_package/test_second_package. Полный discover остаётся прежним.
Новый regression-suite запускается явно по examples/benchmark/REGRESSION.md;
он не добавлен в живой запуск по умолчанию и не создаёт расходы модели в CI.

Новые manual-case eval-задания задают agent и test_type (api/ui/kafka), а предметные
docs — в instruction_paths. Reasoning-контекст использует применимые разделы; это меняет переданный system
и требует новых сопоставимых прогонов. Ограничение argv проверяйте также для
собственных дополнений docs, не только поставляемых наборов.
Прежние suite без полей работают, но пример/канал им по догадке не назначается.
Пустые prompts и внешние/некорректные пути теперь отклоняются: исправьте исходный
набор и создайте новый запуск, не переписывая старые снимки и SHA256.

Существующие критерии и независимая приёмка остаются обязательными. Программный
адаптер помечается fixture; без живого CLI/оценок нет утверждения об улучшении
модели или экономии. Предыдущий переход — [UPGRADE_2.3.16.md](UPGRADE_2.3.16.md).
