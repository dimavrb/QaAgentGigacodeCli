# Обновление до 2.3.7

1. Завершите активные внешние действия, сохраните реестры/журналы/доказательства
   вне поставки и обновите пакет целиком по EXTENSIONS.md. Сверьте manifest и
   VERSION: 2.3.7. Не обнуляйте неизвестный исход записи при обновлении.
2. В новой сессии выполните qa_package_info, `/qa:init`, `/qa:doctor`.
   Изменённые инструкции требуют нового managed-плана с актуальными хешами.
3. Настройте установленный jira-defect-creator и фактический Jira/MCP-адаптер.
   Пакет не устанавливает навык и не предоставляет универсальный Jira API.
   При отсутствии навыка, доступа или проекта сохраняйте blocked.
4. Примите state-backed defect_confirmed и задайте его явной ready-зависимостью
   Jira-назначения. Передайте jira_assignment по JIRA_PUBLICATION.md: точный хеш
   расследования, проект, ожидаемые поля, skill и gateway policy/state.
5. Ограничьте gateway одним create/одной попыткой; согласуйте разрешённое чтение
   для reconciliation. Настройте issue_key_pointer под реальный ответ адаптера.
   Сохраняйте полный поиск, прочитанных кандидатов, квитанцию и чтение полей.
6. При unknown сначала выполните согласованное чтение. Не создавайте другой
   gateway/step_id для того же дефекта. Исправленный отчёт получает новый
   request_id/result_path с прежней операцией. Неподтверждённый исход остаётся
   blocked; автоматического второго create нет.

Исторические JSON, состояния и hashes не меняются. Без новых параметров CLI
сохраняет структурный аудит, но старый отчёт сам не подтверждает публикацию
для нового ready/verified/finish/checkpoint. Диагностический context доступен.
Не дописывайте новые поля в принятые артефакты. Сначала проверяйте переносимый
пример с подставным клиентом, затем один отдельно разрешённый случай в Jira;
локальные тесты не подтверждают интеграцию с реальным сервером.
