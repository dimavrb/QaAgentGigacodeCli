# Обновление до 2.3.14

Для новой установки при уже подключённом профиле QA extension версии 2.3.14
выполните /qa:init в GIGACODE из папки приложения. Команда сама подготовит
исходник внутри проекта, выполнит первую установку и локальные init/doctor.
После установки откройте новую сессию и проверьте /agents manage, /skills и /memory.
Команда не появится в чистом клиенте без подключённого профиля.

Существующую проектную установку 2.3.13 один раз обновите между сессиями
установщиком из нового выпуска:

```bash
python3 /path/to/qa-agent-2.3.14/scripts/qa_install.py --project-root /path/to/app --apply
```

После перехода из корня приложения настройте alias:

```bash
alias qa-start='python3 .qa-agent/package/scripts/qa_start.py'
qa-start
```

Для новых терминалов сохраните alias в своём shell-профиле. Следующие обновления
qa-start проверяет и применяет перед запуском GIGACODE. Новая /qa:init не заменяет
используемый пакет. Подробности установки и восстановления — PROJECT_INSTALLATION.md.
При конфликтах сохраните и рассмотрите адаптации до замены. Состояния задач,
доказательства и исторические хеши не переписываются.

Если используется прежний глобальный extension, сохраните его настройки и
подключите профиль нового выпуска штатным способом вашей сборки; установщик
не редактирует глобальный registry. Сеть и shell-tool нужны для bootstrap,
внешние Python-пути и QA MCP не требуются. Ошибки доступа не обходятся.

Для офлайн-запуска используйте qa-start --no-update. Если CI недоступен или QA-работа
незавершена, launcher сообщает о переносе обновления и запускает текущую версию.
После нового major требуется ручная установка. Конфликты/повреждение не обходятся.
