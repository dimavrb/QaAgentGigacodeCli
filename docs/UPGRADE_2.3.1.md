# Обновление до 2.3.1

1. Завершите активные QA-сессии. Обновите весь пакет штатным способом по
   [EXTENSIONS.md](EXTENSIONS.md) и [AUTO_UPDATE.md](AUTO_UPDATE.md). Автообновление
   принимает только опубликованный commit после успешного CI; локальные изменения
   можно передать в тестовый профиль как целый локальный пакет. Версии `VERSION`
   и `gigacode-extension.json` должны совпасть: `2.3.1`.
2. Откройте новую сессию, получите `qa_package_info`, выполните `/qa:init` и
   `/qa:doctor`. Существующий `.qa-agent/APP_CONTEXT.md` не заменяется: добавьте
   нужные сведения о подготовке/наблюдении и детализации по обновлённому шаблону
   самостоятельно, сохранив подтверждённые настройки и не добавляя секреты.
3. Для тестовой задачи используйте назначение из
   [TEST_CASE_PILOT.md](TEST_CASE_PILOT.md). Передайте требования, актуальное
   покрытие и контекст возможностей; сохраняйте ID неизменившегося поведения.
   Каталог сохраняет schema_version: 1; причины отбора и зависимости — в плане.
4. Новые managed-планы должны фиксировать новые инструкции и context_builder.
   Не пересчитывайте хеши старого плана или принятой ревизии. Изменение пакета
   требует нового управляемого плана по существующему протоколу; история сохраняется.
5. Проверьте план, каталог и существенные решения независимым ревью. Открытые
   зависимости execution не дают готовности запуска; вопросы planning оставляют
   затронутые сценарии вне готового каталога. Публикация в TMS требует собственного
   назначения и проверки представления; эта версия её автоматически не запускает.

Защита обновления и ограничения восстановления из 2.3.0 сохраняются. При переходе
с 2.2.x сначала учтите [UPGRADE_2.3.0.md](UPGRADE_2.3.0.md).
