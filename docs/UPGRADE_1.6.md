# Как установить обновлённую поставку QA-агента 1.6

Актуальная сборка — **2026-10-07**, с проверкой подозрения на дефект. VERSION остаётся 1.6; точная сборка определяется SHA-256 ZIP и датой PACKAGE_MANIFEST.json. Прежний ZIP храните отдельно: файлы разных сборок называются одинаково.

1. Сохраните рядом `qa-agent-1.6.zip`, `.zip.sha256` и `UPDATE_1.6.md`.
2. Передайте агенту задание ниже. Обновление включает вложенный пакет и подключённые QA-роли; локальный контекст, настройки, состояние и журналы сохраняются. Исходный ZIP установленной сборки оставьте как базу сравнения и отката, отдельно от нового одноимённого файла. Если уже установлена первая 1.6, сравнивайте SHA-256, не только VERSION.
3. После обновления откройте новую сессию Qwen Code из привычного корня. Проверьте QA-роли через `/agents` и команду `/qa` через `/help`. Результаты установки должны быть в `UPDATE_REPORT.md`.

Замените пути и передайте агенту:

```text
Обнови QA-агента до обновлённой поставки 1.6 по приложенной UPDATE_1.6.md.
INSTALL_ROOT: /абсолютный/путь/к/установленному/qa-agent
APP_ROOT: /абсолютный/путь/к/проекту/приложения
ARCHIVE_PATH: /абсолютный/путь/к/qa-agent-1.6.zip
CHECKSUM_PATH: /абсолютный/путь/к/qa-agent-1.6.zip.sha256
BASE_ARCHIVE_PATH: /абсолютный/путь/к/прежней/сборке/qa-agent-1.6.zip
BACKUP_ROOT: /новый/каталог/резервной/копии/вне/qa-agent

Проверь поставку и сделай резервную копию. Обнови пакет, подключённые
QA-роли и APP_QWEN.md, сохрани локальные адаптации и контекст приложения.
Проверь перенос DEFECT_VERIFICATION.md и defect_verification.py,
а также обновление координатора, qa-feature-tester, qa-test-automation
и qa-defect-investigator. Новые подозрения требуют verification_required=true
и verification_artifact; результат принимается с --investigation-state.
Сохрани существующие журналы, состояние задач и доказательства.
Выполни локальные проверки по RELEASE_1.6.md и сохрани UPDATE_REPORT.md.
Не выполняй тесты приложения ради обновления и не создавай коммит.
```

Если установлена 1.5 или другая версия, BASE_ARCHIVE_PATH указывает именно её исходный ZIP.

Для отдельной установки: `APP_ROOT: не применяется`. Если прежний ZIP неизвестен: `BASE_ARCHIVE_PATH: неизвестно`; отличающиеся файлы сравниваются адресно, без слепой замены.

В актуальную 1.6 включена проверка подозрения через существующего qa-defect-investigator: бизнес-правило, сохранённое наблюдение, относящийся код и только недостающая адресная проверка. Дефект и причина принимаются отдельно. После обновления не нужно отдельно просить ретест; назначение расследования предусмотрено инструкциями координатора. Проверка этого поведения живой моделью остаётся отдельной приёмкой.

Сохраняются стандарт подготовки данных, чек-лист и выбор разделов по роли, журнал сбоев и правила названий тестов/Allure-шагов. Старые состояния расследований совместимы. Для продолжения старого подозрения включайте новый флаг в отдельном назначении и сбрасывайте прежнее ревью; исторические результаты не переписывайте. Новых ролей нет — всего 10. Журнал и runner работают на macOS/Linux или в WSL.

Локальная приёмка — 151 тест, новый синтетический пример verification/ с проверкой результата и состояния, отдельный учебный рецепт данных, учебный журнал (3 события / 2 инцидента) и частичный бизнес-отчёт по `RELEASE_1.6.md`. Это проверка пакета; доступ к модели, коду приложения, стенду и отображение Allure в реальном репозитории проверяются отдельно.

Для журнала используйте `FAILURE_JOURNAL.md`, для названий — `AUTOTEST_NAMING.md`. Внутри ZIP все инструкции находятся в `docs/`. Рядом с ZIP: `INSTALL_1.6.md` для первой установки в приложение, `SETUP_AND_UPDATE_1.6.md` для отдельной установки и настройки.
