# QA-пакет 2.3.7 — подтверждённая публикация Jira

qa-jira-defect-creator принимает независимый jira_assignment с точным принятым
state-backed defect_confirmed, Jira/проектом, установленным навыком, согласованными
полями и gateway. Без scope возможен blocked. Проверки выполняются при назначении,
передаче, регистрации, ревью и повторном использовании результата.

Публикация подтверждается полным поиском дублей и чтением/оценкой каждого
кандидата. Найденный подходящий дубль исключает create; duplicate_found не может
скрывать совершённую запись. Created требует квитанции одного verified-create,
точных согласованных аргументов и отдельного чтения фактически сохранённых полей.
Ключ, URL, проект, первичные доказательства и версия расследования проверяются
на согласованность; вложенные материалы получают хеши реестра.

Для операции действует предел одного create и одной попытки через ActionGateway.
Timeout/unknown запрещает следующую запись до reconciliation. Тот же дефект
в текущем реестре не может получить новый файл gateway или step_id для обхода
неизвестного результата. Подтверждённый объект переиспользуется; неполный поиск
с отсутствием результата не разрешает повтор. Новый retry автоматически
не выполняется. Между разными реестрами смысловые дубли проверяет координатор.

Исторические отчёты и хеши не переписываются. Их структурный CLI-аудит остаётся;
новые ready/verified/finish/checkpoint требуют подтверждения публикации.
Документы роли, координатора, самопроверки, маршрутов и bare-контекста обновлены.

## Проверки

Полный набор: **903 теста, OK**. Новые **25 проверок** покрывают создание
и найденный дубль, приёмку/вердикт и точную версию расследования, state-backed
источник, late blocking, полноту поиска и чтение каждого кандидата до create,
сохранённые поля/идентификаторы/URL, свежесть наблюдений, неизменность квитанции,
аргументы операции, timeout и восстановление без второго create, запрет повтора
после неавторитетного отсутствия, смену gateway и подмену старого scope,
первичные доказательства, обязательность guard, исторический context,
verified/finish/создание и повторное использование checkpoint, scope/skill/policy,
CLI, bare-контекст и документированный путь до завершения синтетической задачи.

Отдельно прошла **41 проверка совместимости** общего контракта, передач между
ролями и проверки дефектов. Окончательный полный прогон выполнен после проверки
порядка чтения кандидатов и защиты прежнего scope.

```bash
python3 -m unittest discover -s tests -p test_jira_publication.py -v
python3 -m unittest discover -s tests -v
python3 scripts/package_agent.py --output-dir /tmp/qa-agent-2.3.7 --date 2026-10-15
python3 scripts/package_agent.py --verify /tmp/qa-agent-2.3.7/qa-agent-2.3.7.zip
```

Это проверки локального протокола с подставным клиентом, не живого навыка,
Jira или качества GIGACODE. Валидатор не удостоверяет происхождение вручную
сохранённых снимков; координатор оценивает их содержание и достоверность.
