# Настройка и обновление QA-пакета

Текущий профиль — **GIGACODE CLI, 2.1.3**. Первая установка — [INSTALL.md](INSTALL.md),
перенос в приложение — [IMPORT_INTO_APP.md](IMPORT_INTO_APP.md), переход с предыдущей версии —
[UPGRADE_2.1.3.md](UPGRADE_2.1.3.md). Прежние релизные документы доступны в истории Git; текущая поставка содержит
инструкции только для GIGACODE и общего CLI-контракта.

Обновляйте весь пакет: общие инструкции, роли, skills, команды, валидаторы и
примеры. Не заменяйте только файлы ролей. Сохраните предыдущий ZIP/commit и
локальные адаптации до обновления. Runtime-состояния, gateway-журналы, общий
browser_pool и доказательства храните вне заменяемых каталогов.

Если пакет подключён к приложению, обновите исходную копию `qa-agent/`, затем
адресно подключённые `.gigacode`-файлы и `qa-agent/APP_COORDINATOR.md`. Не затирайте
GIGACODE.md приложения, локальные MCP, auth и разрешения. Перед продолжением
старой задачи сверяйте назначения, hashes и фактическое состояние внешних действий.
Изменённые инструкции требуют нового managed-плана.

После обновления:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/agent_runtime.py --mode automation
python3 scripts/agent_runtime.py --mode gateway
gigacode
```

В новой сессии проверьте `/memory`, `/agents manage`, `/skills`, `/help` и `/mcp`.
Различайте «файлы установлены», «CLI совместим», «инструменты доступны» и
«продуктовый сценарий выполнен». Локальные тесты не закрывают живую приёмку.

Для ZIP проверьте checksum и manifest:

```bash
python3 scripts/package_agent.py --verify /absolute/path/qa-agent-2.1.3.zip
```

Для отката восстановите пакет и согласованные адаптации из предыдущего commit/ZIP.
Не восстанавливайте старую runtime-копию поверх актуальных действий или lease.
Перед переключением остановите активных исполнителей и закройте их браузеры.

При разработке самого пакета повышение версии, changelog и инструкция перехода
обязательны для каждого коммита изменений поставки по [AGENTS.md](../AGENTS.md).
