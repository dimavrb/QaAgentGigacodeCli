# Настройка и обновление QA-пакета 2.3.13

1. Установите полную проектную копию по [PROJECT_INSTALLATION.md](PROJECT_INSTALLATION.md).
2. Заполните `.qa-agent/APP_CONTEXT.md`: продукт, требования, сборка, ограничения,
   каталог кейсов, репозиторий автотестов и согласованные пути состояния.
3. Выполните `/qa:doctor` и проверьте роли, навыки, команды и memory в новой сессии.
4. Начните с задачи по требованиям. Создание, список и чтение реестров используют
   локальные Python-команды по [TASK_STORAGE.md](TASK_STORAGE.md), без QA MCP-сервера.
5. Для продуктовых проверок настройте нужные внешние системы отдельно: стенд,
   браузерный профиль по BROWSER_PROFILES.md, данные по TEST_DATA.md, Jira по
   JIRA_PUBLICATION.md. Не переносите credentials или профиль другого проекта.
6. Обновляйте весь комплект отдельным PR между сессиями по [UPDATE.md](UPDATE.md).

Модель и авторизацию задавайте в установленном GIGACODE. Установщик не заменяет
`.gigacode/settings.json` приложения и не выдаёт прав на внешние записи.
Управляемое исполнение сохраняет свои проверки адаптера и scoped gateway по RUNTIMES.md.
