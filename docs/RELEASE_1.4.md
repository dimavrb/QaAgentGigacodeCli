# Поставка QA-агента 1.4

Дата: 2026-10-02. Пакет: `qa-agent-1.4.zip` и `qa-agent-1.4.zip.sha256`. Полный состав и хеши исходных файлов находятся внутри ZIP в `qa-agent/PACKAGE_MANIFEST.json`.

Для передачи поставки используйте ZIP, checksum и инструкцию `UPDATE_1.4.md` для обновления либо `INSTALL_1.4.md` для первой установки в проект приложения. Эти файлы рядом с архивом являются копиями `docs/UPDATE.md` и `docs/IMPORT_INTO_APP.md` из пакета. Общая инструкция — `docs/SETUP_AND_UPDATE.md`, сведения о проверке конкретного ZIP — внешний `VALIDATION_1.4.json`. Старые архивы и инструкции 1.3 сохраняются отдельно и не заменяются.

## Практические изменения

| Изменение | Что проверяет агент |
| --- | --- |
| Добавленное покрытие автотестов | Какой критерий или риск обнаруживает новый тест сверх существующего набора |
| Повторяемая подготовка | Применимость фикстуры/профиля, наблюдаемую готовность, изоляцию и очистку данных |
| Обнаружение штатным прогоном | Новый тест и его варианты включены в collection/discovery с реальными фильтрами репозитория или CI |
| Критичные assert | Контролируемый неправильный ответ вызывает падение на нужной проверке; после удаления подмены тест проходит |
| Исправление тестов | Источник ожидания и исходные проверки сохраняются; зелёный результат не достигается ослаблением assert |
| Компактная модель поведения | Правила решений, переходов или свойств связаны с требованиями, источниками и сценариями |
| Проверяемые комбинации | Попарные и заданные более сложные взаимодействия покрыты с учётом ограничений и обязательных комбинаций |
| Ревью через контрпримеры | Для существенного неправильного поведения существует конкретная обнаруживающая проверка |

Основные документы: `AUTOTEST_QUALITY.md` и `TEST_DESIGN.md`. Новый локальный инструмент — `scripts/generate_combinations.py`; учебные примеры — `examples/test-design/` и `examples/autotest-quality/`. Внешний запуск `run_test_automation.py` передаёт абсолютный путь к стандарту качества, без встраивания всего документа в начальный промпт.

Для простой задачи сохраняется обычный маршрут без новой роли или обязательного дополнительного цикла. Расширенные проверки выбираются по риску. Недоступность эксперимента или discovery отражается как ограничение, а не как выполненная проверка. Математическое покрытие сочетаний не подтверждает ожидаемое поведение и полноту требований.

## Совместимость и обновление

По сравнению с обновлённой 1.3 форматы QA-событий, тест-плана и каталога `schema_version: 1` не меняются. Материалы качества передаются через существующие артефакты. Принятые кейсы не требуют переписывания; новые правила применяются при новом или содержательном изменении плана/автотеста. Для ранней 1.3 и более старых несовместимых результатов выполняется миграция раздела 4 `UPDATE.md`.

Обновляйте вложенный пакет, подключённые роли и `APP_QWEN.md` вместе. Сохраняйте сокращённый корневой `QWEN.md`, `APP_CONTEXT.md`, локальные tools, MCP и артефакты. Проверяйте адаптацию новых ссылок с префиксом `qa-agent/` и доступность стандарта качества из внешнего репозитория. Учебные модели и фикстуры не являются сведениями о приложении. Версия Playwright MCP остаётся `0.0.83`.

## Проверки поставки

До сборки и из распакованной копии в новом каталоге выполняются:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_test_cases.py --input examples/test-cases.json
python3 scripts/validate_qa_result.py --input examples/analysis/result-partial.json --task-id QA-HANDOFF --request-id analysis-2 --agent qa-analyst
python3 scripts/validate_qa_result.py --input examples/handoffs/feature-blocked.json --task-id QA-HANDOFF --request-id feature-2 --agent qa-feature-tester --scenario-id TC-001 --scenario-id TC-002
```

Проверка учебных сочетаний из корня пакета; результат создаётся в новом временном каталоге:

```bash
QA_COMBINATIONS_DIR=$(mktemp -d)
python3 scripts/generate_combinations.py --model examples/test-design/combinations.json --output "$QA_COMBINATIONS_DIR/combinations.json"
python3 scripts/generate_combinations.py --model examples/test-design/combinations.json --check "$QA_COMBINATIONS_DIR/combinations.json"
```

Это проектные комбинации, не готовый каталог кейсов. Для реального готового набора автор добавляет связи scenario_ids и выполняет проверку `--catalog`; координатор отдельно проверяет соответствие значений и ожиданий источникам.

Учебный автотест должен обнаруживаться через discovery. Запуски без подмены проходят с кодом 0; два запуска с подменой должны завершиться кодом 1 с `AssertionError` и указанной причиной, а не с ошибкой импорта, timeout или иной причиной:

```bash
env -u QA_EXAMPLE_FAULT python3 -m unittest discover -s examples/autotest-quality -p 'test_*.py' -v
QA_EXAMPLE_FAULT=status python3 -m unittest discover -s examples/autotest-quality -p 'test_*.py' -v
env -u QA_EXAMPLE_FAULT python3 -m unittest discover -s examples/autotest-quality -p 'test_*.py' -v
QA_EXAMPLE_FAULT=owner python3 -m unittest discover -s examples/autotest-quality -p 'test_*.py' -v
env -u QA_EXAMPLE_FAULT python3 -m unittest discover -s examples/autotest-quality -p 'test_*.py' -v
```

Для `status` ожидается `unexpected order status`, для `owner` — `foreign order owner`. Эти два падения являются ожидаемыми отрицательными проверками учебной фикстуры; они не должны прерывать проверку восстановления. Изменения продукта и общих данных не выполняются.

Внутренние размеры и SHA-256 проверяет `scripts/package_agent.py --verify <архив>`. Внешний checksum проверяется из каталога с ZIP и checksum:

```bash
shasum -a 256 -c qa-agent-1.4.zip.sha256
```

В архив не включаются Git, IDE, кэши и результаты рабочих задач. Проверки реального Qwen, браузера и штатного CI приложения выполняются отдельно после установки при доступном окружении. Локальные и синтетические тесты не подтверждают качество решений живой модели или экономию времени и токенов. Для сравнения используйте одинаковые задачи и условия по `EVALUATION.md` и `examples/benchmark/README.md`.
