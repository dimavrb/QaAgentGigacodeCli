# Обновление до 2.3.16

Завершите активные QA-назначения и managed-планы, закройте сессии GIGACODE.
Обновляйте весь комплект с сохранением локальных адаптаций и доказательств.
После публикации и успешного CI точного коммита проектный launcher 2.3.14+
может применить выпуск командой `qa-start --update-only`.

Для ручного обновления получите проверенную копию 2.3.16, выполните preview,
рассмотрите конфликты и затем примените:

```bash
python3 /path/to/qa-agent-2.3.16/scripts/qa_install.py --project-root /path/to/app
python3 /path/to/qa-agent-2.3.16/scripts/qa_install.py --project-root /path/to/app --apply
```

Запустите локальный doctor и откройте новую сессию для загрузки ролей/skills.
Для managed-работы создайте новые планы с актуальными хешами инструкций.
Старые реестры, критерии, каталоги и архивы не мигрируются заменой строк/хешей.
Правила применяются к новым и существенно изменённым кейсам; незатронутые
принятые кейсы массово не переписываются. Формат каталога остался прежним.

При новой редактуре применяйте «Краткость без потери смысла» TEST_CASE_STYLE:
убирайте повторы, сохраняя условия и проверяемые критерии. Лимита слов нет;
массовое сокращение принятых кейсов не требуется.

До передачи нового кейса автор и reviewer сверяют различающие данные, источник
ожиданий и силу наблюдения по TEST_CASE_STYLE/TEST_CASE_REVIEW. Обязательный
аудит или чтение БД нужны только для соответствующего критерия. При неизвестном
способе сохраняется вопрос planning, при временно недоступном известном —
условие execution. Обновление пакета само по себе не даёт доступа к наблюдателям
и не подтверждает качество живой модели. Прежний порядок перехода с глобального
extension — [UPGRADE_2.3.15.md](UPGRADE_2.3.15.md).
