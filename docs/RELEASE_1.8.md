# Поставка QA-агента 1.8

Дата: **2026-10-07**. Архив: qa-agent-1.8.zip; checksum: qa-agent-1.8.zip.sha256. Внутренний PACKAGE_MANIFEST.json фиксирует версию, дату, размеры и SHA-256 файлов. Специализированных ролей — **11**, навыков — 2, команда — /qa.

## Изменения относительно 1.7

- Локальный общий пул Playwright: одно владение на исполнителя, атомарное резервирование между процессами, повтор назначения без второго профиля. При занятых playwright-a/b/c — очередь.
- Короткий UI-набор с сохранением условий и авторизации; освобождение после доказательств до анализа/ожидания/отчёта. Cleanup обязателен на успехе, ошибке, блокере и отмене; прерванного владельца обслуживает координатор.
- Закрытие контекста/профиля принимается по доказательству текущего lease/close_id. Закрытие только вкладки, ошибочный MCP-результат и старое подтверждение не освобождают запись. Потерянный CLI-ответ не требует второго MCP-close.
- Expiry/неясное закрытие переводят ресурс в карантин. Передача для восстановления требует подтверждения остановки прежнего владельца и отсутствия других клиентов, не одного TTL. Другие активные профили не затрагиваются.
- Отдельные шаблоны isolated/persistent; дубли userDataDir, включая symlink, и незаполненные persistent-пути отклоняются. Существующие каталоги и MCP/settings сохраняются.
- Правила встроены в qa-browser-repro, координатора и нужные роли. Подробный BROWSER_PROFILES.md читается по разделам только для UI. Схема QA-событий не меняется; жизненный цикл передаётся артефактом.

Все возможности 1.7 (REST/Kafka-заглушки), 1.6 (проверка подозрений, данные, журнал, названия), отчётность и планирование сохраняются.

## Установка и совместимость

Переход с 1.7 — UPGRADE_1.8.md и UPDATE.md; первая установка — IMPORT_INTO_APP.md либо SETUP_AND_UPDATE.md. В поставке рядом с архивом — UPGRADE_1.8.md, UPDATE_1.8.md, INSTALL_1.8.md, SETUP_AND_UPDATE_1.8.md, RELEASE_1.8.md и внешний VALIDATION_1.8.json.

Универсальные MCP/settings не заменяют настройки приложения. Для постоянных профилей сохраните реальные userDataDir и авторизацию; заполните persistent-pool.json вне Git. Один абсолютный browser_pool_path используется всеми клиентами этих ресурсов. Runtime-реестр и пользовательские профили не входят в ZIP и не заменяются при обновлении. Для начального принятия ресурс в карантине; для работающего реестра повторный init запрещён.

Пул кооперативный, локальный, требует POSIX/flock (macOS/Linux/WSL) и общей файловой системы с корректными locks. Он не вызывает MCP, не закрывает процессы сам и не блокирует прямой обход протокола. Работа между хостами/контейнерами не подтверждена. Физическое освобождение и истинность сохранённых доказательств проверяются отдельно.

Результаты QA, каталоги, stub-схема v2, журналы и расследования сохраняют свои форматы. При откате остановите текущих владельцев/выполните cleanup; не восстанавливайте старую runtime-копию поверх актуальных lease. 1.7 не использует новый пул.

Python 3.10+, стандартная библиотека. Playwright MCP остаётся 0.0.83. Архив не содержит Git/IDE/cache, dist, пользовательских данных, рабочего состояния и доказательств. Прежние ZIP и инструкции сохранены.

## Проверки пакета

Из корня распакованного пакета:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_test_cases.py --input examples/test-cases.json
python3 -m unittest discover -s examples/test-data -v
```

Ожидаются **196 тестов пакета** и один отдельный учебный тест данных. Пул отдельно: `python3 -m unittest discover -s tests -p test_browser_pool.py -v` — 18 тестов, включая шесть одновременных процессов на один ресурс, три владельца/четвёртый ожидает, expiry, невалидные close, recovery и одинаковые persistent-каталоги. Эти проверки не открывают браузер.

Полный CLI-цикл проверяется на синтетических материалах: init (quarantined), принятие после остановки прежнего владельца, finish-close, acquire, check/heartbeat, begin-close, finish-close и status. Persistent-шаблон с незаполненными путями должен отклоняться. После заполнения тестовыми путями init не создаёт userDataDir и не запускает браузеры.

Для учебных команд заглушек используйте RELEASE_1.7.md: намерение до MCP, черновик, configure_only и verify; без внешнего назначения/полного набора ID результат отклоняется. Для отчётности, журнала, расследования и выбора разделов данных — команды «Проверки поставки» RELEASE_1.6.md. Исторические 178/151 тест относятся к старым версиям; актуальный набор — 196.

Протокол конкретного ZIP фиксирует проверки исходников и распакованной копии, манифеста/checksum, состава, соответствия файлов и инструкций, новых CLI-циклов и прежних возможностей. Живой Qwen, Playwright/sbermock, продуктовый CI, Allure и A/B модели при сборке не проверяются. Экономия токенов/времени неизвестна.

## Проверка в рабочем окружении после установки

По BROWSER_PROFILES.md проверьте фактическую доступность серверов и семантику close, повторную выдачу после закрытия контекста/профиля, cleanup после ошибки/отмены и независимость B/C при восстановлении A. Проверку повторного открытия проводите с новым lease и своим cleanup. Приёмка реестра без продуктовых действий возможна только после подтверждения остановки старых владельцев; при неизвестном состоянии сохраняйте карантин. Файлы установки и готовность UI учитываются отдельно.
