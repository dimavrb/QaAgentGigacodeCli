# Обновление с 2.1.4 до 2.1.5

В 2.1.5 исправлена установка из Git URL и добавлен автоматический запуск обновления
до сессии. Предыдущие инструкции direct Git install не подходят целевой сборке.

1. Завершите активную QA-работу, сохраните предыдущую поставку и локальные адаптации.
2. Сохраните исходный пакет отдельным Git clone по [EXTENSIONS.md](EXTENSIONS.md).
   Если локальная копия уже есть, обновите её через `git pull --ff-only origin main`.
   Версии VERSION и манифеста должны совпадать: для этого выпуска `2.1.5`.
3. Установите/обновите extension штатным менеджером из этой локальной папки.
   Если ранее источник установки был другим, сначала переподключите источник
   через поддерживаемый вашей сборкой порядок установки; не меняйте registry руками.
4. Откройте новую сессию из продукта и выполните `/qa:init`, `/qa:doctor`.
   Контекст, кейсы и результаты сохраняются. Изменение installed path требует
   проверенного `--rebind`; файл прежней локальной привязки не удаляйте вслепую.
5. Настройте alias `qa-start` из [AUTO_UPDATE.md](AUTO_UPDATE.md) и дальше
   запускайте QA-сессии через него. Первый запуск запишет локальный источник;
   повторные будут автоматически проверять обновления до открытия CLI.

Для нескольких проектов выполните первичное подключение каждого; используйте
один local clone и профиль блокировки для общей установки. Начните новый managed-
план по новым инструкциям, сохранив старые hashes/журналы/внешние действия.
Живой порядок native update требует пилота на вашей сборке GIGACODE.
