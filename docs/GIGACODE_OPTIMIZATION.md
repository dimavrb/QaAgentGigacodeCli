# Контекст GIGACODE и переносимые инструкции

`GIGACODE.md` импортирует только короткие общие правила `docs/COORDINATOR.md`.
Предметные стандарты читаются по роли и этапу. Managed-сборщик передаёт их снимки
явно, хранит hashes и не обрезает доказательства ради лимита.

## Чтение координатором

Для первого обращения получи заголовки, затем выбранные разделы. Команды
разрешают пути от установленного пакета независимо от cwd продукта:

```bash
python3 <package_root>/scripts/read_qa_instructions.py document --path docs/TASK_STORAGE.md --list
python3 <package_root>/scripts/read_qa_instructions.py document --path docs/TASK_STORAGE.md --section "Найти и продолжить работу"
python3 <package_root>/scripts/read_qa_instructions.py role --agent qa-test-plan-writer
```

`--section` повторяется для нескольких разделов. Вступление перед первым `##`
включается всегда; неизвестный или повторяющийся заголовок вызывает ошибку,
без молчаливого пропуска. Секция `role` возвращает весь frontmatter, включая
описание и tools, без тела роли. Этого достаточно для маршрутизации и проверки
заявленных инструментов; предметные обязанности координатор сверяет отдельно.
Исполнитель по-прежнему получает полную роль, managed-сборка не меняется.

| Этап | Документ и разделы, добавляемые к уже прочитанным правилам |
| --- | --- |
| Создание | TASK_STORAGE: «Создать задачу локальным CLI»; TASK_ACCEPTANCE: «Согласованные критерии» |
| Передача | TASK_EXCHANGE: «Назначение и результат», «Самопроверка автора»; TASK_ACCEPTANCE: «Готовность для исполнения и информационный контекст» |
| Приёмка/завершение | TASK_ACCEPTANCE: «Оценка критериев»; предметный протокол ревью |
| Восстановление | TASK_STORAGE: «Найти и продолжить работу», «Команды и старые пути»; фактический qa_tasks.py get |
| Вопросы/ожидание | Соответствующие разделы TASK_EXCHANGE и QUESTIONS_UI |

Таблица не отменяет инструкции выбранного маршрута. Изменение области, старый
формат или неизвестный риск требуют дочитать применимые разделы. Не читай заново
тот же неизменённый текст на каждом ходе; после новой сессии восстанови нужные
правила и состояние через `/qa:resume`, проверив владельцев и доказательства.

## Передача и первичные источники

Назначение сохраняй в JSON без эха содержимого. Используй `manage_task.py ...
prepare --request-id <ID> --expected-revision <N> --output <новый handoff.json>`.
В историю координатора попадает квитанция; исполнителю передаётся полный
`result` файла по TASK_EXCHANGE. Не подменяй его кратким пересказом. Существующий
файл не перезаписывается; неизвестный исход требует чтения реестра до повтора.
Для `start` извлеки локально только `result.delivery_id`; не выводи весь файл
в историю ради одного поля. Передавай полный файл через доступный механизм
входов исполнителя, сохраняя проверку хеша и обязательных материалов.

Для установки читай сводку `qa_project.py doctor`: версию, статусы и failed-
проверки. Полный install.json с парами путь/hash выводи только для конкретной
диагностики. Сам doctor продолжает сверять полный манифест локально.

В Jira запрашивай явно выбранные поля, необходимые для требований, критериев,
связей и версии задачи, если инструмент поддерживает выбор полей. Загружай
subtasks/issuelinks и связанные задачи по необходимости покрытия; отсутствие
запрошенного поля не означает отсутствие требований. Сохраняй первичный ответ
в артефакт с идентификатором источника, а в историю возвращай путь и нужный
фрагмент. Аналогично читай относящиеся к задаче разделы proposal/дельта-спек,
сохраняя зависимости, ограничения и точные ссылки. Неполная область источника
должна быть явно отмечена; сокращение вывода не разрешает терять доказательства.

## Контекст клиента и измерения

Настройка `tools.eager` не входит в профиль: её совместимость и эффект
в GIGACODE не подтверждены. Поставка содержит документированную секцию MCP,
без изменения auth, модели и политик разрешённых действий.

В именованных субагентах сохранены явные allowlist tools там, где они были заданы;
роли инфраструктуры наследуют инструменты установки. Сверяйте имена по `/tools`
в своей сборке. При недоступном tool возвращайте конкретный блокер. Не расширяйте
allowlist для обхода ограничения и не снимайте ограничения целевого проекта.

Для контроля стоимости используйте `/context detail` в новой сессии и одинаковые
контрольные задачи. Измеряйте фактические токены, время, качество и все повторы;
число символов не является токенами. Сокращение файла не доказывает экономию.

При отдельном runner frontmatter не ограничивает весь headless runtime. Контракт,
preflight и пределы изоляции описаны в [RUNTIMES.md](RUNTIMES.md). Успешный preflight
не является проверкой поведения флагов или live-приёмкой.
