# Пути и состояние QA extension

В режиме extension различай `package_root` (установленный QA-пакет) и
`project_root` (текущий продуктовый репозиторий). Получи фактический путь и версию
пакета через read-only MCP `qa_package_info`; не вычисляй их из имени Git-репозитория
или предполагаемого домашнего каталога. Инструмент не читает проект и не пишет файлы.

`/qa:init` прежде всего вызывает MCP `qa_project_init` с абсолютным
`project_root` и `rebind=false` (по умолчанию). Он вызывает `initialize()` напрямую
без subprocess и сохраняет локальную привязку версии/пути в
`.qa-agent/project.local.json`, создаёт шаблон `.qa-agent/APP_CONTEXT.md`, если его
ещё нет, и дополняет `.gitignore` только правилами локального QA-состояния.
Существующий контекст и настройки приложения не заменяются. При переносе пакета
на другой путь первый вызов без `rebind` возвращает `isError` с CLI-текстом
`QA project error: …` и старым/новым путём. Покажи оба пути пользователю и установи
причину; только для разрешённого переноса вторым вызовом той же MCP-сессии
передай `rebind=true`. Изменение путей или перезапуск MCP требует нового показа.
Показ путей сам по себе не разрешает перенос. Повторение на том же пути обновляет версию.
Инициализация не переносит продуктовые кейсы и не подключает внешние системы.

Для автообновления используй `qa-start` по `docs/AUTO_UPDATE.md`. До сессии он
проверяет локальный clone и заменяет установленную копию штатным менеджером CLI.
После смены пакета перезапускает свой код и обновляет привязку новым инициализатором.
`.qa-agent/update.local.json` хранит путь источника без секретов; проектные контекст,
кейсы, runtime-состояние и доказательства при обновлении не заменяются.

Перед QA-задачей вызови read-only MCP `qa_project_doctor` с абсолютным
`project_root`. Он вызывает `doctor()` напрямую; единственный дочерний процесс —
зонд `gigacode --version`. `needs_attention` — штатный результат, ошибки
чтения/структуры возвращаются как `isError` с `QA project error: …`.
Ошибка привязки версии
требует `/qa:init`, ошибка CLI/MCP — настройки доступности. `ready_for_cli_check`
означает только готовность локальных файлов к проверке сессии; это не live-приёмка.
Если соответствующий MCP-инструмент недоступен, используй CLI fallback:
`python3 "<package_root>/scripts/qa_project.py" init|doctor --project-root "<project_root>"`
(выбери одну команду). Перед CLI `--rebind` также сначала прочитай привязку,
покажи оба пути и проверь разрешение переноса. CLI требует
`--expected-binding-sha256` из первой ошибки; MCP сравнивает показанный binding
под той же блокировкой, что и запись. Не обходи `isError` через CLI.
Защита обновления, независимый rollback и fsync — [UPDATE_SAFETY.md](UPDATE_SAFETY.md).

## Правила разрешения путей

Единая раскладка новых планов/кейсов/расследований, список заданий и восстановление
описаны в [TASK_STORAGE.md](TASK_STORAGE.md). `/qa:tasks` использует read-only
`qa_tasks_list`, `/qa:resume <ID>` — `qa_task_get`. Пустая `/qa` сначала показывает
незавершённые задания и предлагает выбрать. MCP не запускает и не принимает
назначения; сохраняй проверку владельцев и expected-revision из TASK_EXCHANGE.md.
Нестандартный старый реестр открывай по явно заданному пути, без переноса истории.

- Пути `docs/`, `scripts/`, `examples/`, `.gigacode/` из инструкций QA относятся
  к `package_root`. Читать надо `<package_root>/docs/...`, запускать Python —
  `python3 "<package_root>/scripts/имя.py" ...`.
- Продуктовые файлы, источники требований, кейсы и тесты относятся к
  `project_root`. Текущую рабочую директорию оставляй продуктовой; не выполняй
  `cd` в пакет для запуска скрипта и не создавай продуктовые файлы внутри extension.
- Для доказательств по умолчанию используй `<project_root>/.qa-agent/artifacts/`,
  для managed-состояния — `<project_root>/.qa-agent-state/`. Явные пути назначения
  сохраняют приоритет. При общем browser_pool используй согласованный внешний путь.
- Передавай каждому исполнителю оба абсолютных корня, версию и абсолютные пути
  применимых инструкций. При отсутствии корней восстанови их до работы; не
  выбирай одноимённые `docs/` или `scripts/` из приложения как QA-стандарты.
- Контекст продукта — `.qa-agent/APP_CONTEXT.md`; читай только нужные разделы.
  Существующее `qa-agent/APP_COORDINATOR.md` является локальной адаптацией: проверь
  её применимость и версию до использования. Не удаляй старую установку автоматически.

Для исходной Git-копии и старой установки без extension остаются существующие
пути из `IMPORT_INTO_APP.md`. Содержимое installed extension не редактируй для
настройки приложения; меняй контекст проекта или проектные переопределения.
При совпадении имён ролей/команд проверь фактически выбранные CLI компоненты.
