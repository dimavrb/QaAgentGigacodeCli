# Пути и состояние QA-пакета

Основной режим с 2.3.13 — [проектная установка](PROJECT_INSTALLATION.md).
QA MCP-сервер отсутствует. `project_root` — фактический корень приложения,
`package_root` — его `.qa-agent/package/`. Сначала проверь `.qa-agent/install.json`
и выполни `/qa:doctor` локальным `scripts/qa_project.py`. Прерванная установка,
изменённые файлы или несовместимая версия требуют исправления до QA-работы.
Отсутствующий пакет установи через /qa:init по PROJECT_INSTALLATION.md;
не угадывай путь глобального extension и не создавай ручной реестр.

- `docs/`, `scripts/`, `examples/`, `.gigacode/` в инструкциях относятся к package_root.
- Скрипты запускай по абсолютному пути внутри проекта, сохраняя cwd=project_root.
- Передавай каждому исполнителю оба вычисленных абсолютных корня и версию.
- Продуктовые файлы, контекст `.qa-agent/APP_CONTEXT.md`, задачи `.qa-agent-state/`
  и доказательства `.qa-agent/artifacts/` находятся вне заменяемой папки package.
- Общий browser_pool использует согласованный абсолютный путь без копирования состояния.
- Для другого execution workspace установи пакет в нём; путь основного проекта
  для отдельного репозитория всё ещё является внешним.

`/qa:init` при отсутствии установки сначала получает исходник в проектную
bootstrap.local и выполняет первую установку. Для готового пакета вызывает локальный `qa_project.py init --project-root <project_root>`;
в проектном режиме версия и путь выводятся из переносимого install.json, абсолютный
binding не публикуется. Контекст создаётся лишь при отсутствии, настройки сохраняются.
`/qa:doctor` вызывает read-only `qa_project.py doctor`; проверяет hashes, версию,
профиль и доступность CLI. `ready_for_cli_check` не означает live-приёмку.

Новые задачи создавай через локальный `qa_task_create.py --criteria <file>`.
Список и чтение — `qa_tasks.py list|get`; продолжение — проверяемые операции
`manage_task.py` с актуальными ревизиями. Детали — TASK_STORAGE.md и TASK_EXCHANGE.md.

В исходном репозитории пакета package_root — сам репозиторий; старый явный
project.local.json поддерживается только для прежних установок. Его перенос
требует рассмотренного --rebind с digest. Проектный install.json имеет приоритет
над старой локальной привязкой. Не переносить старые состояния и frozen-планы
заменой строк. Метаданные доступны через `qa_project.py info`, без MCP.

Проектный qa-start перед открытием CLI проверяет обновления по UPDATE.md.
Незавершённая QA-работа/открытая сессия откладывает обновление, но не продолжение
старой версии. При успешном обновлении launcher загружается заново под той же
блокировкой. --no-update запускает установленную копию без сетевой проверки.
