# Управление Playwright-профилями

Читай нужный раздел только для UI-работы через MCP. Для API-only, анализа кода, отчёта и запуска обычных автотестов с собственными fixtures пул не нужен. Настройка текущего пакета описана в INSTALL.md и SETUP_AND_UPDATE.md.

## Настройка

playwright-a/b/c — имена MCP-серверов, не доказательство независимых профилей. Сопоставь реальные настройки: isolated либо разные фактические абсолютные userDataDir для persistent. Переименование сервера не устраняет общий каталог. Сохрани условия браузера/авторизации и локальные ограничения; не переключай persistent на isolated автоматически. CDP/extension/remote/shared браузер нельзя объявить выделенным только через конфиг пула.

Все исполнители и GIGACODE-сессии используют **один абсолютный browser_pool_path**, включая другие проекты/рабочие копии, если они обращаются к этим же ресурсам. Не создавай отдельный пул на задачу. Реестр локальный: POSIX/flock, macOS/Linux или WSL, один хост и файловая система с корректными locks. Между хостами или при обходе скрипта взаимное исключение не гарантируется.

Скопируй examples/browser-pool/pool.json в локальную конфигурацию вне Git и укажи реальные имена и режимы. Для persistent укажи user_data_dir, например {"server":"playwright-a","mode":"persistent","user_data_dir":"/absolute/path/to/profile-a"}. Конфиг не создаёт MCP-серверы. Credentials/cookies не записывай. Runtime-реестр храни вне заменяемого пакета.

Для трёх постоянных профилей с разными userDataDir начни с examples/browser-pool/persistent-pool.json и замени все REPLACE_WITH_ACTUAL_PATH фактическими путями. Сохрани существующие каталог/режим/авторизацию. Не используй isolated-шаблон для объявления этих же persistent-серверов изолированными. При уже различных каталогах причина удержания пока unknown: проверь исполнение cleanup, незавершённые браузерные процессы и другие MCP-клиенты, вместо добавления профиля D.

```bash
python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  init --config /absolute/path/to/local/pool-config.json

python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json status
```

Первоначально ресурсы в карантине: старые браузеры могут быть заняты. Для принятия используй раздел восстановления. Не перезаписывай существующий реестр. Конфиг отклоняет дубли серверов и persistent-директорий, включая symlink; соответствие фактическому MCP проверяет координатор.

## Владение и короткие UI-наборы

Назначение содержит browser_pool_path, доступный manage_browser_pool.py и фактический GIGACODE owner_task_id. task_id/request_id — из QA-назначения. Получи ресурс непосредственно перед UI, не заранее:

```bash
python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  acquire --task-id QA-123 --request-id QA-123-ui-1 --owner-task-id ACTUAL_GIGACODE_OWNER
```

Ответ содержит server/lease_id; работай только на этом MCP-сервере. --server ограничивает ресурс при обязательных условиях теста. Повтор назначения возвращает тот же lease; владелец не резервирует второй. Не придумывай owner_task_id. Вкладки одного контекста разделяют storage и не являются отдельными ресурсами.

Перед короткой серией и после ожидания продли владение:

```bash
python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  heartbeat --server playwright-a --lease-id RETURNED_LEASE_ID
```

TTL по умолчанию 300 секунд, --ttl 30..3600 при выдаче; срок должен превышать ограниченный MCP-вызов и обработку доказательств. При отказе check/heartbeat прекрати UI. **Expiry не освобождает браузер**, а переводит в карантин. Истёкшее владение нельзя продлить для UI. Старый владелец может только закрыть свой ресурс, пока recovery не передал его другому. Реестр не блокирует MCP напрямую: перед передачей координатор останавливает прежнего исполнителя.

Объединяй небольшой последовательный набор с одинаковыми стендом/пользователем, проверяя предусловия каждого кейса. Сохраняй авторизацию внутри набора; освобождай профиль после доказательств **до анализа кода, отчёта, ожидания вопроса/данных/ревью**. Для следующего UI-этапа получи новый lease и восстанови условия. Не закрывай после каждого клика и не держи ресурс на всё расследование.

Если свободных нет, команда возвращает блокер сразу. Координатор читает status: активных не прерывает ради нового кейса, карантинные восстанавливает адресно, UI ставит в очередь до сигнала освобождения. Не создавай четвёртый сервер и не опрашивай в цикле. Продолжай независимый анализ; общий блокер свяжи с зависимыми ID по EXECUTION.md.

## Закрытие при любом исходе

На success/failed/blocked/отмене/ошибке выполняй cleanup как finally. Если исполнитель прерван, ответственность принимает координатор.

1. Сохрани screenshot/snapshot/console/network и последний шаг, без новых продуктовых действий.
2. begin-close с server/lease-id возвращает close_id и closing_started_at, запрещает новые UI-действия. Повтор не меняет close_id.
3. На **том же выделенном сервере** фактически закрой контекст/освободи профиль. Проверь семантику browser_close установленной версии: закрытие только страницы недостаточно. Не записывай успех по названию инструмента.
4. Сохрани безопасный первичный результат в close.json с фактическим временем и контекстом, затем finish-close --evidence. Реестр становится free только после принятия доказательства. Структура/hash не доказывают истину; координатор оценивает реальные материалы.

```bash
python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  begin-close --server playwright-a --lease-id RETURNED_LEASE_ID

# Владелец вызывает MCP-закрытие и сохраняет фактический результат.

python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  finish-close --server playwright-a --lease-id RETURNED_LEASE_ID \
  --evidence /absolute/path/to/close.json
```

Форма close.json (шаблон не доказательство; замени значения фактическими):

```json
{
  "server": "playwright-a",
  "lease_id": "RETURNED_LEASE_ID",
  "close_id": "RETURNED_CLOSE_ID",
  "observed_at": "2026-10-07T12:00:00+03:00",
  "scope": "context",
  "success": true,
  "profile_released": true,
  "method": "фактически выполненное закрытие выделенного контекста",
  "result": {"первичный результат": "подтверждение закрытия"}
}
```

Принимаются scope=context/server и непустой result; tab/ошибка/старое время/чужой lease отклоняются. Если MCP предоставляет код с page, для **исключительно принадлежащего lease** контекста возможен `await page.context().close()` через доступный инструмент: он закрывает все страницы контекста. Для persistent может требоваться освобождение выделенного процесса. Не вызывай browser.close() у общего CDP/extension/browser-сервера. При неподдерживаемом закрытии — карантин и адресное переподключение владельцем; универсальную команду restart не выдумывай.

После close не проверяй свободу через navigate/snapshot/вызов, лениво открывающий браузер: это может снова занять ресурс. Используй результат close и доступную диагностику выделенного процесса/lock без открытия. Проверка повторного запуска — отдельная операция с новым lease и cleanup.

Для локального выделенного **persistent context**, запущенного через launchPersistentContext, закрытие контекста закрывает и его браузер. Это штатный способ завершить процесс без удаления userDataDir; сохранённая авторизация остаётся в профиле. Проверь, что конкретный MCP действительно использует этот режим, прежде чем применять пример через доступный инструмент выполнения с page:

```javascript
async (page) => {
  await page.context().close();
  return { scope: 'context', persistent_context_closed: true };
}
```

Применяй только на server своего lease после begin-close и сохранения доказательств. Не подставляй пример в browser_evaluate: он работает внутри страницы, а не с серверным Playwright Page. Ошибку MCP после закрытия не превращай в success автоматически: сохрани факт и оставь карантин до подтверждения. Для CDP/extension/общего браузера этот рецепт не назначается. [Семантика launchPersistentContext](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context).

При timeout/неясном результате — quarantine --reason, один инцидент с server/lease_id/owner и доказательствами. Прошедший продуктовый кейс не подтверждает техническую очистку. Повтор finish-close с тем же неизменённым доказательством после потерянного CLI-ответа допустим до новой выдачи; повторять MCP-close ради него не нужно. План закрытия не является восстановлением.

## Восстановление и первичное принятие

Прочитай status, прекрати UI-вызовы прежнего владельца, проверь завершение/остановку его работы и отсутствие неучтённых клиентов. TTL этого не доказывает. Для начального карантина старые браузеры также могут существовать без lease.

Сохрани stopped.json: server, previous_lease_id (текущий старый ID либо явный null при первичном принятии), prior_owner_stopped=true, connections_quiesced=true, method с источником и observed_at после текущего changed_at. Флаги по догадке запрещены.

```bash
python3 scripts/manage_browser_pool.py \
  --pool /absolute/path/to/app/.qa-agent-state/browser-pool.json \
  begin-recovery --server playwright-a --task-id QA-123 \
  --request-id QA-123-recovery-1 --owner-task-id ACTUAL_COORDINATOR_OWNER \
  --evidence /absolute/path/to/stopped.json
```

Только quarantined с доказательством текущего поколения; активный lease не крадётся. Recovery возвращает новый lease_id/close_id, старые команды владельца реестр отклоняет. Выполни закрытие/переподключение только этого выделенного сервера и finish-close по новому доказательству. Активные B/C не затрагиваются. Нельзя удалять реестр, browser-locks или общий userDataDir, выполнять killall Chrome или закрывать всех после ошибки одного.

До free не назначай ресурс для продукта. Если владелец/сервер/права недоступны — один блокер и продолжение независимой работы. Принимаются фактические материалы восстановления, не только обновление JSON.

## Проверки и перенос

Локальные регрессии: `python3 -m unittest discover -s tests -p test_browser_pool.py -v`. Пример — examples/browser-pool/README.md. Они не открывают браузер.

В приложение перенеси browser_pool.py/manage_browser_pool.py, этот документ, новый qa-browser-repro и правила координатора/исполнителей вместе. Адаптируй ссылки к qa-agent/docs/scripts/examples, сохрани существующий runtime-реестр и MCP/settings. Версия браузерного сервера не меняется. Жизненный цикл (server/lease/owner/времена/закрытие либо карантин/hash доказательства) передаётся ссылкой в artifacts роли без изменения QA-события. Координатор принимает освобождение отдельно от результата продукта.

В живом окружении проверь повторную выдачу после закрытия всех страниц/контекста, cleanup после ошибки/отмены, ожидание четвёртой задачи и независимость B/C при ошибке A. Измеряй время ожидания/владения, число блокировок/восстановлений и фактическое покрытие. До замера ускорение неизвестно.

Источники: [режимы профилей и параметры MCP 0.0.83](https://github.com/microsoft/playwright-mcp/blob/v0.0.83/README.md#user-profile), [BrowserContext.close](https://playwright.dev/docs/api/class-browsercontext#browser-context-close). Persistent допускает одного браузерного владельца; isolated теряет storage при закрытии. Документированный --idle-timeout для видимого браузера по умолчанию отключён; после проверки локальной версии согласованный timeout может дополнять cleanup, но не обновляет реестр и не заменяет подтверждение. Не задавай короткое значение, прерывающее допустимое ожидание/авторизацию.
