# QA-пакет 2.3.14 — установка и обновление одним действием

/qa:init при подключённом QA extension получает исходник официального репозитория
в уникальную .qa-agent/bootstrap.local/install.*/source и запускает установщик оттуда.
Все исполняемые Python-файлы находятся внутри проекта. QA MCP-сервер не добавляется.
После установки выполняются локальные init/doctor; для загрузки новых ролей нужна
новая сессия клиента. Повтор использует установленную версию без скачивания/обновления.

--bootstrap разрешает открытую сессию только для первой установки из staging-папки.
Уже установленный или частичный пакет не заменяется этим режимом; незавершённые
QA-задачи/планы, конфликты, pending и блокировки остаются обязательными проверками.
Терминальное обновление между сессиями и восстановление сохраняются.

Проектный qa-start проверяет main официального репозитория и успешный CI нового
коммита, статически проверяет поставку и импортирует её в отдельном интерпретаторе.
Затем новый установщик обновляет весь комплект, а launcher перезапускается на новом
коде до запуска GIGACODE. Блокировка передаётся между процессами и удерживается
в течение всей сессии. Офлайн, неподтверждённый CI, активные задачи/сессии откладывают
обновление и позволяют открыть текущую проверенную версию. Конфликты останавливают
запуск; major требует ручного перехода. Доступны --no-update и --update-only.
