# Обновление QA-пакета с 2.1.3 до 2.1.4

Новый способ подключения — native GIGACODE extension. Исходная Git-копия и
прежнее подключение через `qa-agent/` продолжают поддерживаться.

1. Сохраните предыдущий commit/ZIP и адаптации приложения, завершите активных
   исполнителей и проверьте исход внешних действий. Runtime-состояния и исторические
   доказательства сохраняйте отдельно; изменение инструкций требует нового плана.
2. Обновите весь пакет и проверьте совпадение VERSION с `gigacode-extension.json`:
   для этого выпуска — `2.1.4`. Установите extension по
   [EXTENSIONS.md](EXTENSIONS.md), сверив возможности вашей сборки CLI.
3. Откройте GIGACODE из приложения и выполните `/qa:init`, затем `/qa:doctor`.
   Для прежней установки отдельно перенесите подтверждённые сведения из
   `qa-agent/APP_CONTEXT.md` в `.qa-agent/APP_CONTEXT.md`; новый шаблон не заменяет
   старую адаптацию автоматически. Сверьте локальный `APP_COORDINATOR.md` с
   новыми правилами разрешения путей. Не переносите секреты и историю задач в контекст.
4. Проверьте дубли ролей, skills и команд в проектной `.gigacode/`. Проектные
   компоненты могут переопределять extension; перед удалением старых файлов
   сравните локальные изменения и получите разрешение на очистку. Старый импорт
   в GIGACODE.md не удаляется инициализатором. Auth/MCP приложения сохраняются.
5. Выполните локальные тесты и пилот в двух проектах по `EXTENSIONS.md`.
   Обновление файлов и совпадение версии не доказывают совместимость CLI.

Если сохраняете прежнее подключение, обновите его по
[IMPORT_INTO_APP.md](IMPORT_INTO_APP.md) и [SETUP_AND_UPDATE.md](SETUP_AND_UPDATE.md).
Чтобы откатиться на 2.1.3, восстановите прежнюю поставку и способ подключения;
актуальные внешние действия, journals, ID-карты и hashes не переписывайте.
