# QA-пакет 2.3.11 — обновление проектных ролей по сохранённой базе

Проектные QA-роли теперь управляются по истории установки: неизменённый
файл заменяется новой версией, локальная адаптация сохраняется, одновременные
изменения дают конфликт. Новые роли и безопасные изменения других ролей
применяются независимо от конфликта. Общий `needs_attention` блокирует новую
сессию через `qa-start`, пока конфликты не рассмотрены.

История в `.qa-agent/agents.local.json` хранит базовые хеши/версии по ролям.
Предыдущие исходники, резервные копии и неизменяемые журналы намерений находятся
в `.qa-agent/agent-updates/`. Init добавляет их в ignore, сохраняя контракт трёх
проектных файлов. Снимки и pending публикуются до изменения роли; повторный
`--apply` восстанавливает прерванную операцию по фактическим хешам.

Принятие рассмотренной адаптации требует актуальных хешей local/incoming через
`--accept-local`; локальное удаление не отменяется без `--restore`. Убранные
из пакета неизменённые роли архивируются и удаляются из каталога обнаружения,
адаптированные сохраняются как конфликт. Повреждённая история блокирует запись.

`qa-start` запускает синхронизацию из установленного пакета после binding refresh
и до GIGACODE, включая `--update-only` и `--no-update`. При общей блокировке
сессий разрешён только preview. Неподключённые проекты не получают копии
автоматически. Старые копии без истории требуют первого явного `--apply`.
Doctor читает историю без записи и допускает адаптации при неизменившейся базе.

Порядок — [PROJECT_AGENT_UPDATES.md](PROJECT_AGENT_UPDATES.md), переход —
[UPGRADE_2.3.11.md](UPGRADE_2.3.11.md). Прямой `gigacode` не вызывает sync;
живой CLI и его native hooks в этой среде не проверены. Исторические задания,
хеши, runtime и доказательства не мигрируются.

Проверки выполняются командами:

```bash
python3 -m unittest discover -s tests -p test_agent_role_updates.py -v
python3 -m unittest discover -s tests -p test_project_agents.py -v
python3 -m unittest discover -s tests -p test_extension_project.py -v
python3 -m unittest discover -s tests -p test_auto_update.py -v
python3 -m unittest discover -s tests -p test_update_hardening.py -v
python3 -m unittest discover -s tests -v
```

Результат: 23 теста правил обновления и восстановления, 10 тестов проектного
установщика, 24 теста привязки/MCP, 26 тестов автообновления и 18 тестов
защиты/отката — OK. Полный набор: 976 тестов, OK. Проверка launcher использует
фиктивный CLI и подтверждает обновление проектной роли до запуска сессии.
Тесты процессов/серверов выполнены вне песочницы, блокирующей `ps`.
ZIP версии 2.3.11 с 503 файлами проверен по манифесту.

Файловая синхронизация и синтетический CLI не подтверждают качество живой
модели. После установки проверьте новую сессию, `/agents manage`, вызов роли
и возврат координатору; `live_agents_verified` остаётся false до живой проверки.
