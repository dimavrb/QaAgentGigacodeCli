# Обновление QA-агента до 1.5

Главное изменение: отчёт объясняет, какие действия и бизнес-правила проверялись, что ожидалось, что наблюдалось и что осталось непроверенным. Он также показывает условия, фича-тогглы и историю повторов. В пакете 10 специализированных ролей, включая новую `qa-test-report-writer`.

## Как обновить установленного агента

1. Сохраните рядом `qa-agent-1.5.zip`, `qa-agent-1.5.zip.sha256` и `UPDATE_1.5.md`. Завершите текущий прогон и сохраните результаты.
2. Передайте эти файлы агенту в своём проекте вместе с заданием ниже. Инструкция обновляет пакет и подключённые QA-компоненты, сохраняя сокращённый QWEN.md приложения, APP_CONTEXT.md, локальные MCP/tools, артефакты и историю. ZIP 1.4 оставьте для сравнения и отката.
3. После обновления откройте новую сессию Qwen Code из привычного корня. Через `/agents` проверьте наличие `qa-test-report-writer`, через `/help` — `/qa`. Локальные проверки должны быть отражены в `UPDATE_REPORT.md`.

Замените пути и передайте агенту:

```text
Обнови QA-агента до версии 1.5 по приложенной UPDATE_1.5.md.
INSTALL_ROOT: /абсолютный/путь/к/установленному/qa-agent
APP_ROOT: /абсолютный/путь/к/проекту/приложения
ARCHIVE_PATH: /абсолютный/путь/к/qa-agent-1.5.zip
CHECKSUM_PATH: /абсолютный/путь/к/qa-agent-1.5.zip.sha256
BASE_ARCHIVE_PATH: /абсолютный/путь/к/исходному/qa-agent-1.4.zip
BACKUP_ROOT: /новый/каталог/резервной/копии/вне/qa-agent

Проверь поставку, сделай резервную копию и обнови также подключённые
QA-роли и APP_QWEN.md. Сохрани локальные настройки и контекст приложения.
Проверь пакет и учебную отчётность, затем сохрани UPDATE_REPORT.md.
Не выполняй тесты приложения ради обновления и не создавай коммит.
```

Для отдельной установки задайте `APP_ROOT: не применяется`. Если прежний ZIP отсутствует, задайте `BASE_ARCHIVE_PATH: неизвестно`; инструкция предусматривает адресное сравнение файлов.

## Как проверить новую отчётность

Из корня установленного пакета `qa-agent/` выполните:

```bash
python3 -m unittest discover -s tests
QA_REPORT_CHECK_DIR=$(mktemp -d)
python3 scripts/build_test_report.py --scope examples/test-reporting/scope.json --runs examples/test-reporting/detailed-runs.json --revision install-check --output-dir "$QA_REPORT_CHECK_DIR/report"
python3 scripts/build_test_report.py --check "$QA_REPORT_CHECK_DIR/report"
```

Откройте `report.md` в созданном каталоге. Учебная оплата при new_checkout=ON описана действиями и наблюдением; OFF не проверен, отмена и возврат заблокированы. Ожидается 1 из 3 выполненных проверок. Это синтетический пример, без запуска приложения.

Для рабочего отчёта передайте координатору:

```text
/qa Подготовь отчёт по сохранённым результатам тестирования задачи <ID>.
Область и бизнес-кейсы: <путь к scope.json>.
Результаты, условия и ревью прогонов: <путь к runs.json>.
Покажи бизнес-цель, правило, записанные действия, ожидание, факт,
тогглы и непроверенную область прямо в отчёте. Ссылки оставь основаниями.
Не запускай новые проверки. Неизвестные условия и подробности не выдумывай.
```

Подготовку scope/runs/review описывает `TEST_REPORTING.md`. При отсутствии метаданных попросите координатора составить их по доступным источникам. Условия старого прогона нельзя восстанавливать по текущим значениям стенда. Подробный отчёт ограничен содержанием первичных результатов.

Прежние QA-события 1.4 и каталог кейсов совместимы. Для `test_report_ready` нужен валидатор 1.5; при откате новые отчёты сохраняются отдельно вместе с входами и версией сборщика.

Для первой установки используйте `INSTALL_1.5.md`, для отдельной установки и настройки — `SETUP_AND_UPDATE_1.5.md`. Внутри ZIP этим файлам соответствуют `docs/IMPORT_INTO_APP.md` и `docs/SETUP_AND_UPDATE.md`; полная инструкция обновления — `docs/UPDATE.md`.
