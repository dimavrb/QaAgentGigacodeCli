# Поставка QA-агента 1.3

Дата: 2026-10-02. Пакет: `qa-agent-1.3.zip` и `qa-agent-1.3.zip.sha256`. Инструкция обновления: `UPDATE.md`, настройка: `SETUP_AND_UPDATE.md`. Это обновлённая поставка 1.3; её отличает SHA-256 ZIP. Прежний ZIP 1.3 сохраняется отдельно как база сравнения.

## Практические изменения

| Изменение | Результат для работы |
| --- | --- |
| Понятные сообщения | По первым предложениям видно конкретную проблему, влияние и основание вывода; подробности доступны в артефактах |
| Выбор сценариев до подробных шагов | Каждый сценарий связан с критерием/риском и возможной ошибкой; обязательный набор сохраняется при ограничении времени |
| Смысловые дубли | Эквивалентные проверки предлагаются к объединению; отдельные права, границы и состояния сохраняются при различии рисков |
| Общие блокеры | Одна проверка недоступного условия связывается с зависимыми ID; независимые сценарии продолжаются |
| Адресное продолжение | При неизменных условиях повторяются только затронутые сценарии; при смене сборки или данных применимость старых результатов проверяется |
| Структурированный анализ | Требования, риски и вопросы связаны по ID; неизвестные ожидания не превращаются в готовые кейсы |
| Полная матрица блокировки | При blocked сохранены все назначенные ID; при смешанном результате и пропуске по времени используется feature_test_complete |
| Проверка готовности | Готовые и заблокированные ID не пересекаются и точно соответствуют назначению |
| Контрольный набор | Пять учебных задач и 20 критериев позволяют оценить решения модели до и после обновления без NDA-материалов |

Это изменения инструкций процесса. Снижение числа повторов, времени и токенов нужно измерять в установленном окружении на одинаковых задачах, а не выводить из прохождения Python-тестов.

## Совместимость и обновление

Форматы тест-плана и каталога `schema_version: 1` сохраняются. Прежние строковые массивы `analysis_ready` нужно преобразовать в структурированные объекты с источниками, статусами и связями. Полная блокировка `qa-feature-tester` теперь требует матрицу результатов всех назначенных ID. Для `environment_partial`, `data_ready`, `data_partial` валидатору обязателен полный набор `--scenario-id`. Миграция описана в разделе 4 UPDATE.md и применяется также к ранней поставке 1.3. Версия Playwright MCP остаётся `0.0.83`; ведомость контрольного набора — отдельный артефакт ручной оценки.

Обновлять нужно вложенный пакет и подключённые роли/инструкции. Сохраняйте APP_CONTEXT.md, сокращённый корневой QWEN.md приложения, локальные tools, MCP и артефакты. Старые принятые каталоги не требуется переписывать ради новых правил. Новые правила отбора применяются при создании или содержательном изменении плана. Архивы 1.1/1.2 остаются базой сравнения и не заменяются.

## Проверки поставки

Перед сборкой и после распаковки в отдельный каталог выполняются:

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_test_cases.py --input examples/test-cases.json
python3 scripts/validate_qa_result.py --input examples/analysis/result-partial.json --task-id QA-HANDOFF --request-id analysis-2 --agent qa-analyst
python3 scripts/validate_qa_result.py --input examples/handoffs/feature-blocked.json --task-id QA-HANDOFF --request-id feature-2 --agent qa-feature-tester --scenario-id TC-001 --scenario-id TC-002
```

Внутренние размеры и SHA-256 файлов проверяет `scripts/package_agent.py --verify <архив>`, внешний checksum — `shasum -a 256 -c qa-agent-1.3.zip.sha256`. В архив не включаются Git, IDE, кэши и результаты рабочих задач.

Локальные тесты включают синтетическую передачу результатов между девятью ролями по examples/handoffs/; это проверка контракта, не запуск ролей живой моделью.

В среде сборки команда Qwen недоступна: контрольный набор живой моделью и браузерная интеграция не выполнялись. После установки выполните набор по `examples/benchmark/README.md` в отдельной тестовой установке. Скрипт ведомости подтверждает полноту записанной ручной оценки и хеш ответа; он не определяет семантическую правильность.
