# Playwright MCP для воспроизведения дефектов

Подключение находится в `.gigacode/settings.json`, профиль — в `.gigacode/playwright.config.json`. Закреплена опубликованная версия `@playwright/mcp@0.0.83`. Навык `qa-browser-repro` используется исполнителями UI-расследований и ручных проверок. Владение, освобождение и восстановление — по нужному разделу [BROWSER_PROFILES.md](BROWSER_PROFILES.md): один общий реестр и lease на короткий UI-набор. Механизм включён в поставку 1.8.

## Запуск

Нужны Node.js 18+, `npx` в PATH процесса GIGACODE CLI и установленный Google Chrome. Запускай `gigacode` из корня проекта: путь конфигурации относительный. В новой сессии проверь `/mcp` → `playwright` и `/skills` → `qa-browser-repro`. Если Chrome отсутствует, установи его обычным способом либо настрой `launchOptions.executablePath` на разрешённый Chromium. При несовпадении схем сначала проверь версию и активные настройки MCP.

Профиль использует изолированный видимый Chrome: состояние сохраняется во время работы браузера, но не после закрытия. Для независимых расследований нужны разные экземпляры сервера; вкладки не изолируют пользователя. Для дефекта, зависящего от дискового профиля, отключи `isolated` и укажи отдельный `userDataDir`, зафиксировав это условие. Один дисковый профиль использует один процесс.

Автоматический snapshot отключён: читай страницу явно после первого перехода и на границах состояния. Изображения сохраняются без отправки в каждый ответ MCP. Для визуального дефекта открой screenshot через доступный просмотрщик; при необходимости измени `imageResponses` на `allow`. Viewport 1280×720 — стартовое значение; для конкретного дефекта используй исходный размер. Сохраняй свойства продукта, включая service workers и TLS-проверку.

`includeTools` оставляет UI и диагностику. Для дополнительных инструментов добавь нужную capability и имя, затем переподключи сервер. Подтверждения GIGACODE CLI работают по текущим настройкам, `trust` не включён. При обновлении версии проверь параметры запуска, схемы и smoke-сценарий.

## Короткая серия

Первый проход по неизвестному экрану выполняй с наблюдениями. После изучения формы можно объединить стабильный участок. Пример для `browser_run_code_unsafe`; имена элементов заменяются подтверждёнными именами реального экрана:

```javascript
async (page) => {
  const completed = [];
  try {
    await page.getByRole('textbox', { name: 'Поиск', exact: true }).fill('QA-123');
    completed.push('Ввести QA-123 в поиск');
    await page.getByRole('button', { name: 'Найти', exact: true }).click();
    completed.push('Нажать Найти');
    const result = page.getByRole('status');
    await result.waitFor({ state: 'visible', timeout: 5000 });
    return { completed, url: page.url(), actual: await result.innerText() };
  } catch (error) {
    return { completed, url: page.url(), error: String(error), state: 'incomplete' };
  }
}
```

`incomplete` завершает серию и требует нового наблюдения. Если следующий шаг зависит от неизвестного ответа, выполняй его отдельно. Для независимых полей проще `browser_fill_form`; формат массива бери из схемы подключённого инструмента.

## Smoke-проверка и замер

На разрешённой тестовой странице выполни navigate → snapshot → заполнение формы → действие → ожидание результата → snapshot. Проверь сохранение авторизации и доступность screenshot с явно заданным именем. Собери console/network до следующего перехода. После закрытия браузера новое открытие должно начать изолированную сессию.

Сравни несколько запусков одного сценария с известным дефектом: исходные настройки и новый профиль при одинаковых модели, MCP-версии, стенде, сборке и предусловиях. Считай время до проверяемого вывода, вызовы и объём ответов; токены бери только из фактического usage. Оба режима должны обнаружить тот же дефект и сохранить пригодные доказательства. До сравнения ускорение остаётся гипотезой. Общие критерии — в `docs/EVALUATION.md`.

Артефакты браузера исключены из Git. Credentials не сохраняются в настройках проекта. Если нужен storage state, используй локальный файл вне Git и опиши восстановление сессии без секретов в отчёте.

Источники параметров: [Playwright MCP](https://github.com/microsoft/playwright-mcp) и [MCP GIGACODE CLI](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/mcp). Схемы установленного сервера имеют приоритет над примерами документации.
