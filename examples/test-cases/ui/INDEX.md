# Примеры UI

Выбери один файл по цели текущей проверки. Не загружай все примеры. Контракты,
названия форм, маршруты, тексты, диапазоны и способы очистки здесь учебные:
замени их подтверждёнными требованиями и возможностями приложения.

| Цель | Пример |
| --- | --- |
| Создание через форму и подтверждение | [create.json](create.json) |
| Обязательные поля и сохранение введённых значений | [validation.json](validation.json) |
| Допустимое граничное значение формы | [boundary.json](boundary.json) |
| Доступ к защищённой странице | [permissions.json](permissions.json) |
| Фильтрация и сброс состояния | [filter.json](filter.json) |

Если точного совпадения нет, используй ближайший пример оформления, не добавляя его сценарий в покрытие. Второй пример читай только для другого существенного аспекта, который не показан первым.

Стандарт UI-кейса: **Шаг — Ожидаемый результат — Тест-дата** по
[TEST_CASE_STYLE.md](../../../docs/TEST_CASE_STYLE.md). Действие хранится в name,
конкретное состояние экрана — в expected_result, значения полей/фильтра,
выбранные ID и ожидаемые строки/тексты — в необязательном текстовом test_data.
Без данных поле опускается; в таблице отображается `—`. HTTP-блоки request/response
не нужны для обычного UI-действия.

Связанные поля формы объединяются в логическое заполнение; отправка остаётся
отдельным действием со своим результатом. Промежуточное состояние по отдельному
правилу проверяется отдельно. Применение фильтра объединяет выбор и нажатие
«Применить»; пустая выдача не заменяет ожидаемый непустой набор.

В create.json номер ORDER_ID берётся из фактического подтверждения и используется
при поиске созданной строки и очистке; его обозначение не сравнивается дословно.
В validation.json пустой email задан явно, а ожидаемый текст находится у
конкретного поля. Учебные кнопки удаления, маршрут и тексты не являются
возможностями вашей системы. Видимый результат не доказывает внутреннюю запись
в БД или серверный отказ API.
