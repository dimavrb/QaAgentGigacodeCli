# Структурированные результаты аналитика

`result.json` связывает два подтверждённых учебных требования с TC-001 и TC-002. Источники находятся в `../test-plan/requirements.md`; этот пример передаётся синтетическому автору плана в `../handoffs/routes.json`.

`result-partial.json` использует исходный снимок `requirements-initial.md`: ожидание TC-002 неизвестно, поэтому expected_result и expected_source равны null. Вопрос Q-1 блокирует его проектирование, пробел G-1 сохраняется, TC-001 остаётся независимым. Это другая учебная стадия, а не утверждение о поведении реального продукта.

Проверка из корня пакета:

```bash
python3 scripts/validate_qa_result.py --input examples/analysis/result-partial.json --task-id QA-HANDOFF --request-id analysis-2 --agent qa-analyst
```

Схема и правила связей описаны в `docs/CONTRACT.md`, раздел «Результат аналитика». Старые массивы строк не поддерживаются; при миграции нельзя придумывать отсутствующие источники. Структурная проверка не заменяет оценку источников координатором.
