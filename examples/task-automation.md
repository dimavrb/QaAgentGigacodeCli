# Пример задания для qa-test-automation

Замените этот пример реальными данными перед запуском.

task_id: QA-EXAMPLE-1
request_id: QA-EXAMPLE-1-autotest-1
цель: добавить регрессионный тест для фильтрации списка по статусу
источник ожидаемого поведения: ссылка на критерий приёмки
сценарий: при выборе статуса список содержит только элементы этого статуса
окружение: укажите тестовое окружение и версию
данные: укажите способ создания элементов с разными статусами
стандарт данных: ядро через доступный абсолютный путь к scripts/read_test_data_guide.py --role qa-test-automation; справочник TEST_DATA.md дочитывать по нужным разделам
профиль исходного состояния: путь к действующей фикстуре/seed, восстановление и проверка готовности
штатный прогон: реальная команда репозитория/CI и способ проверить обнаружение нового теста
добавленное покрытие: какой ранее непокрытый критерий или вариант закроет тест
контролируемая ошибка: для критичного assert подмешать запись другого статуса в изолированной фикстуре; сохранить целевое падение и восстановление, либо конкретное ограничение
стандарт качества: доступный абсолютный путь к docs/AUTOTEST_QUALITY.md из QA-пакета
стандарт названий: доступный абсолютный путь к docs/AUTOTEST_NAMING.md из QA-пакета; язык и соглашения целевого проекта, каталог при наличии
проверка названий: условие и результат совпадают с источником и assert, проверочные шаги выполняют assert; приложить свежий результат с именами и вариантами/Allure-шагами либо конкретное ограничение
проверка данных: обязательные свойства и видимость подтверждены, попытки изолированы, очистка работает после частичного сбоя; приложить доказательства либо ограничения
критерии готовности: адресный запуск выполнен, штатное обнаружение подтверждено, критичный assert проверен по согласованному критерию, результат и изменения переданы на независимое ревью; ограничения явно сохранены
