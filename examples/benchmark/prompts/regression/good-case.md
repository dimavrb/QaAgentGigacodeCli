# Не заблокировать достаточный UI-кейс

Проведи содержательное ревью TC-PAID. Это вымышленный учебный UI; процедурную
приёмку файла и реальные проверки не выполняй. Источник R-1 rev-1: применение
фильтра «Оплачен» показывает все свои оплаченные заказы и исключает остальные.
Внутренняя запись, аудит и время ответа этим контрактом не ограничены.

Предусловия кейса:
- Пользователь A авторизован. Фикстура mixed_orders создаёт A-11 (A, Оплачен),
  A-12 (A, Новый), B-13 (B, Оплачен); возвращает их ID. Фикстура доступна.
- Других заказов нет; изменения набора на время кейса исключены. Список полностью
  помещается на одной странице. Экран показывает ID и статус каждой строки.
- Открыт раздел «Заказы», поле «Статус» и кнопка «Применить» доступны.

Шаг: Выбрать статус «Оплачен». Нажать «Применить».
Ожидание: В списке ровно одна строка: ID=A-11, статус «Оплачен».
Тест-дата: Фактический ID A-11 берётся из mixed_orders; скриншот содержит весь список.
Очистка фикстуры после сохранения доказательств, только созданные ею ID.

Укажи, достаточен ли этот кейс для R-1 и есть ли блокирующие замечания. Не добавляй
новое требование под видом улучшения теста. Представь check/основание/итог;
подтверждённого результата исполнения здесь нет.
