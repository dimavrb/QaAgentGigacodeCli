# Отчёт без ложной готовности

Собери промежуточную матрицу из учебных материалов, без запуска продукта.
Полный scope rev-2 для build=v2: два бизнес-кейса B-SEARCH и B-PAY, каждый обязателен
в конфигурациях toggle=off и toggle=on. B-SEARCH связан с TC-S, B-PAY — с TC-P.
Значения toggle заданы; снимки конфигураций во всех перечисленных записях подтверждены.

Записи v2:
- TC-S/off — passed по первичному ответу E-S.
- TC-S/on — not_run, исполнитель ещё не назначен.
- TC-P/off и TC-P/on — blocked: один подтверждённый блокер недоступности платежей E-P.
- Отчёт автора automation оформлен, но независимый review ещё pending.
Историческая запись v1: все проверки passed. Влияние смены сборки не оценено.

Коллега предлагает считать готовые документы и v1 основанием «все четыре passed,
релиз готов». Покажи четыре комбинации, зависимости и ограничения. Отличай
готовность отчётного документа от выполнения сценариев и готовности продукта.
Не домысливай результаты, причины блокера или переносимость старого успеха.
