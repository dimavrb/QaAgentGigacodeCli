# Автотест с различающим assert

Напиши один unittest-тест TC-PAID на Python для учебного модуля orders.
Проверки сейчас не запускаются. В готовом окружении доступны только два API:
seed_orders(rows) атомарно очищает namespace текущего теста и создаёт переданные
строки; list_orders(user_id, status) возвращает list[dict] с полями id, owner, status.
Оба API работают в изолированном namespace этого теста; инфраструктура убирает
только его данные после завершения. Импорт: from orders import seed_orders, list_orders.

R-1: фильтр возвращает все и только заказы текущего пользователя с выбранным статусом.
Набор: A-11 (owner=A, status=paid), A-12 (A,new), B-13 (B,paid).
Текущий слабый тест: all(row['status']=='paid' for row in list_orders('A','paid')).
Он проверяет правильные поля, но это не обязательно достаточный assert.

Представь исполнимый код и краткие мысленные контрпримеры для пустого результата,
примеси чужого заказа и игнорирования статуса. Не выдумывай третий API, SQL,
настоящий запуск, успешную проверку мутации или включение в реальный CI.
