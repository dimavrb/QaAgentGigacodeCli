# Сравнение контекста и качества подготовки данных

Три синтетических задания ниже используют только заданные бизнес-правила. Передавай модели один prompt нужной роли, без рубрики и результатов другой версии. Вариант A — инструкции до оптимизации с полным стандартом данных; B — чек-лист, начальные разделы роли и дополнительные разделы по условиям задачи. Одинаковые модель, инструменты, окружение, версия рецепта и исходное задание обязательны. Внешние действия не требуются.

Проверяющий получает фактические ответы обоих вариантов и таблицу ниже. Каждый критерий отмечается pass/fail/not_checked со ссылкой на ответ. Самооценка модели не заменяет независимую оценку; Python-тесты не являются оценкой ответов GIGACODE.

| Задание / роль | Обязательные критерии |
| --- | --- |
| 01-composition / qa-test-data-builder | Есть свой paid, свой unpaid и чужой paid, у каждого назначение; для границы 100 предложены 99/100/101; права не выдуманы сверх источника; рецепт без выполнения не объявлен data_ready |
| 02-lifecycle / qa-test-automation | Изоляция учитывает независимые run и worker; timeout требует проверки фактического создания до повтора; третья операция не оставляет первые ресурсы без очистки; проверяемое списание не заменено установкой paid |
| 03-review / qa-autotest-reviewer | Пустой список — конкретный ложный успех; общие изменяемые данные создают риск конфликтов; частичный setup не достигает finally и требует исправления; без запуска нет подтверждения готовности/очистки стенда |

Для каждого варианта/задания сохраняй исходный ответ и его SHA-256, точную ревизию инструкций и параметры модели, прочитанные разделы, input_tokens/output_tokens из реального usage либо null, wall_seconds либо null, число повторов и замечания. Повтори каждый вариант минимум три раза в новых сессиях, чередуя A/B. Совокупные токены разных ролей считай отдельно от максимального контекста одной сессии. Число символов инструкции — отдельная метрика, не оценка токенов.

Для A/B нужны две изолированные копии пакета с одинаковыми настройками: в A восстанови снимок изменённых инструкций до оптимизации, в B используй новые. Не сравнивай обе версии в одной истории и не используй текущий GIGACODE.md для старого варианта. Снимок базовых файлов и локальные измерения конкретного изменения сохраняются в artifacts/context/ и не входят в поставку. Подготовь одинаковый контекст приложения без NDA-данных. До установки/переключения фиксируй все отличающиеся файлы; путь к селектору у B должен быть доступен из его копии.

При недоступном GIGACODE/модели запиши «не выполнялось»; не заполняй pass, время или токены из оценки текста. Принимай сокращение только при сохранении всех обязательных критериев. Если критерий ухудшился, уточни ядро/условие дочитывания и повтори затронутое сравнение. Экономия на одном простом задании не доказывает экономию на сложном.
