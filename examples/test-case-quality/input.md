# Учебная задача: отбор и конкретизация кейсов экспорта

Все правила, маршруты, наблюдения, роли и данные ниже **синтетические**.
Адрес реального сервиса отсутствует. Ничего не отправляй в реальную TMS.
Подготовь карту решений по кандидатам и каталог готовых ручных кейсов.
Сохрани подтверждённое существенное покрытие, даже если сейчас нельзя выполнить
проверку. Ответы на вопросы и новые продуктовые правила не придумывай.

## Требования

### export

R-1. Роль `analyst` может экспортировать отчёт. Роль `viewer` не может:
кнопка «Экспортировать CSV» у неё отсутствует, `POST /api/exports` отвечает
`403` с `error.code = EXPORT_FORBIDDEN` и не создаёт задания.
Разрешение и запрет — самостоятельные условия одного правила.

R-2. Экспорт относится только к выбранному фильтру и организации пользователя.
Таблица «Счета» после применения фильтра также показывает только счета выбранного
статуса своей организации.
Для фильтра «Оплачен» CSV имеет колонки `invoice_id,status,amount` именно в этом
порядке и только строки `INV-101,paid,100.00` и `INV-102,paid,250.00` из набора
`DATA-PAID`. Порядок строк не определён. Третья строка, пропущенная строка или
чужая организация являются ошибкой. Кнопка «Экспортировать CSV» запускает
экспорт; после готовности задания ссылка «Скачать CSV» скачивает файл.

R-3. Параметр `limit` — целое число от `1` до `1000` включительно. UI использует
неизменяемый список этих значений; других значений в нём нет. При достаточном
количестве подходящих счетов CSV содержит ровно `limit` строк данных.
API принимает JSON `{"filter":"paid","limit":<число>}`. Для `0` и `1001`
возвращает `400`, `error.code = LIMIT_OUT_OF_RANGE`, без создания задания.
Допустимый запрос отвечает `202` с `job_id`.

R-4. Если подходящих счетов нет, результат содержит только строку заголовков
`invoice_id,status,amount`, задание завершается успешно. Точный текст уведомления
UI не задан; придумывать его нельзя.

R-5. Повторные `POST /api/exports` с одинаковым JSON и одинаковым заголовком
`Idempotency-Key` от одного пользователя возвращают один и тот же `job_id`
и создают ровно одно задание. Правило действует и после потери ответа первого
запроса. Редкость потери ответа не уменьшает важность защиты от дублей.

R-6. При несовпадении контрольной суммы готового файла скачивание отклоняется,
повреждённый файл не выдаётся пользователю. Источник не задаёт точного текста
ошибки UI.

### deletion

R-7. Удаление сохранённого отчёта — отдельная операция. После выбора «Удалить»
и подтверждения отчёт не отображается в списке; `GET /api/reports/<id>` отвечает
`404`. Отмена подтверждения оставляет отчёт доступным. Удаление не является
частью сценария экспорта.

### unknown

R-8. В источниках нет правила экспорта архивного отчёта: неизвестны и
доступность операции, и ожидаемый результат. Это отсутствие требования.

## Возможности проверки

| Аспект | Подтверждённая возможность или ограничение |
| --- | --- |
| UI | Страница «Счета»: фильтр «Статус», значение «Оплачен», поле «Лимит», кнопка «Применить», таблица счетов, кнопка экспорта, список заданий и ссылка скачивания. Изменять DOM и обходить список значений в рамках UI-проверки запрещено: для входных данных вне диапазона используется API. |
| Доступ | Тестовые роли `analyst` и `viewer` для организации `ORG-A` доступны через стендовый менеджер доступа. В кейсах указывается роль и способ получения доступа; секреты в каталог не записываются. |
| Данные | Профиль фикстуры `DATA-PAID` создаёт в `ORG-A` два оплаченных счёта `INV-101`/`INV-102` с суммами из R-2, один неоплаченный `INV-103`; в `ORG-B` — оплаченный `INV-201`. Профиль `DATA-MANY` создаёт в `ORG-A` 1001 оплаченный счёт с уникальными ID. Профиль `DATA-DELETE` создаёт сохранённый отчёт `REP-DELETE-1`. Профили выбираются в панели «Данные стенда»; перед каждым запуском создаётся независимый набор. |
| Нет данных сейчас | Профиль `DATA-EMPTY` документирован: отдельная организация без счетов. Сегодня этот профиль временно выключен владельцем стенда. Способ подготовки известен; запрос на повторное включение допустим. |
| Подготовка неизвестна | В панели нет возможности подменить контрольную сумму, и другого подтверждённого способа нет. Правило R-6 известно; механизм подготовки состояния неизвестен. SQL и способ доступа к хранилищу не предоставлены. |
| API и наблюдения | Авторизованный API-клиент доступен через менеджер доступа. `GET /api/exports/<job_id>` возвращает статус и ссылку скачивания. `GET /api/exports` показывает ID заданий текущего пользователя; снимки до/после позволяют проверить, что новое задание не создано или создано ровно одно. Ссылку скачивания берут из фактического задания. API-токены не сохраняются в кейсах. |
| Имитация сбоя | API-прокси стенда имеет переключатель «Оборвать ответ одного POST /api/exports после обработки». Запрос обрабатывается, ответ теряется; следующий запрос проходит без вмешательства. Это разрешённый способ подготовки для R-5. |
| Наблюдение дефекта | Синтетический протокол `OBS-1`: под `analyst` в `ORG-A` после фильтра «Оплачен» CSV содержит ожидаемые `INV-101`, `INV-102` и лишний `INV-201`. Протокол служит входом учебного задания, не реальным результатом теста. |

Профили данных и наблюдения описывают возможности данного задания, не общие
возможности QA-пакета. Пока кейс готовится, тестирование не запускается.

## Кандидаты

Номера `C-*` — ID кандидатов, а не готовых кейсов. До подробных шагов выбери
решение для каждого: отдельный кейс, включение в другой, предусловие, вопрос
или исключение с основанием. Если кандидат требует разделения по способу
проверки, укажи судьбу каждого условия.

| ID | Первоначальная идея |
| --- | --- |
| C-01 | Через UI установить `limit = 0`, отправить запрос и проверить серверную ошибку. |
| C-02 | Отдельный кейс: кнопка «Экспортировать CSV» видна у `analyst`. |
| C-03 | У `analyst` выбрать оплаченные счета, выгрузить файл; проверить, что всё правильно. |
| C-04 | У `analyst` скачать CSV для оплаченных счетов из `DATA-PAID`; убедиться, что файл заполнен. |
| C-05 | Проверить, что `analyst` может успешно создать задание экспорта через API. |
| C-06 | Проверить запрет экспорта для `viewer`; объединить с разрешённым экспортом `analyst` в одном проходе. |
| C-07 | Выбрать минимальный допустимый лимит `1` на `DATA-MANY`; проверить число строк в файле. |
| C-08 | Выбрать максимальный допустимый лимит `1000` на `DATA-MANY`; объединить с лимитом `1`, если кейсов получается много. |
| C-09 | Передать `limit = 1001` через API; получить отказ без задания. |
| C-10 | Экспортировать пустую выборку. Сегодня `DATA-EMPTY` недоступен, поэтому предлагается исключить сценарий. |
| C-11 | Экспортировать архивный отчёт; ожидать сообщение «Архивные отчёты недоступны». |
| C-12 | Подготовить файл с неправильной контрольной суммой и проверить отказ скачивания; способ подготовки не описан. |
| C-13 | Потерять ответ первого создания экспорта и повторить запрос с тем же ключом; предлагается убрать как слишком редкую проверку. |
| C-14 | После экспорта удалить сохранённый отчёт и проверить отмену удаления в том же кейсе, чтобы сократить каталог. |
| C-15 | В `OBS-1` CSV содержит чужой `INV-201`; предлагается заменить ожидание на «файл не пуст», пока не будет уточнения требований. |
