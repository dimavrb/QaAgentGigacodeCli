# Учебный отбор ручных тест-кейсов

Это **синтетический набор**, созданный для проверки маршрута работы с кейсами.
Он не является требованиями реального приложения, экспертной разметкой
продуктовых кейсов или доказательством качества GIGACODE.

- [input.md](input.md) — требования, возможности проверки и 15 кандидатов.
  Передай только этот файл автору кейсов.
- [reviewer-reference.md](reviewer-reference.md) — ожидаемые решения и вопросы
  для независимого ревью. Не передавай его автору до завершения задания.
- [ready-cases.json](ready-cases.json) — пример одного принятого UI-кейса в
  существующем `schema_version: 1`. Это пример конкретизации, а не полный ответ
  на учебное задание.

Автор должен подготовить карту решений и JSON-каталог готовых кейсов. В карте
нужны источник, способ проверки, добавленная польза, решение и сохранённое
покрытие. Новых обязательных полей JSON этот набор не вводит. Вопросы и
зависимости подготовки остаются вне каталога готовых кейсов.

Проверка примера из корня QA-пакета:

```bash
python3 scripts/validate_test_cases.py --input examples/test-case-quality/ready-cases.json
python3 scripts/build_manual_allure.py \
  --catalog-dir examples/test-case-quality \
  --output /tmp/qa-case-quality-allure \
  --namespace synthetic-case-quality \
  --manifest /tmp/qa-case-quality-manifest.json
```

Выбери новые пустые выходные пути, если предыдущие существуют. Генератор не
выполняет продуктовые тесты и не отправляет данные в TestOps. Эти команды
проверяют совместимость структуры и преобразования; полезность и достоверность
кейсов оценивает ревьюер. Реальный пилот описан в
[TEST_CASE_PILOT.md](../../docs/TEST_CASE_PILOT.md).
